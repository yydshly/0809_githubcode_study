# 场景技能层设计合同

## 设计合同

```text
Entry mode: revision-led
Request revision: 1
Target user and context: 已上传一张图片、知道想得到什么用途，但不理解裁剪、Alpha、画布和导出参数的普通用户
Desired first impression: 先看到“我要做什么”，随后仍能检查和微调每一步
Visual ambition: Functional
Experience architecture: Editorial Flow
Visual constraints: 沿用现有任务卡、工作预览、设置卡和结果工作台；场景优先于自由工具，不新增装饰性页面
Information constraints: 明确本地/远程、是否依赖服务、会改变什么、输出什么；不得声称证件合规或 AI 自动质量判断
Operation constraints: 复用现有 EditState、renderer、BackgroundRemovalProvider、蒙版修正和下载合同；不新增后端或模型
State constraints: 服务未配置时远程场景必须不可选；失败不覆盖来源、不自动重试；换处理方向保留当前图片并退休旧结果
Environment constraints: 当前首轮桌面 Chromium；移动与正式发布不在本次范围
Primary journey: 上传并确认图片 → 选择实际用途 → 自动载入场景起点 → 用户微调 → 生成、检查和下载
User-defined phases: 场景技能框架；商品白底图；报名照/底色头像；社交头像与封面；工程与浏览器验收
Required artifacts: scenario-skills.js、场景优先任务选择、三条任务设置与结果合同、测试、状态文档
Autonomy authorization: 用户已明确“确定”，授权在既有产品边界内直接实现
User-decision boundary: 新外部服务、机构证件合规承诺、老照片修复模型、批量/账号/计费不在本次授权内
Observable completion criteria: 三个场景以用户用途出现；场景默认参数实际进入同一 renderer/provider；商品白底默认导出不透明 JPEG；无服务时远程场景关闭；自由工具仍可用
```

## 场景与边界

| 场景技能 | 复用路径 | 默认起点 | 当前承诺 |
| --- | --- | --- | --- |
| 商品白底图 | 本地构图 → 远程抠图 → 本地修边/白底 | 1:1、最长边 1600、白底 JPEG | 制作普通商品展示图；不做平台合规、阴影或批量 |
| 报名照 / 底色头像 | 本地头肩构图 → 远程抠图 → 本地修边/选底 | 1:1、人物位置略上移、白底起点 | 普通报名和头像用途；不承诺护照、签证或机构受理 |
| 社交头像与封面 | 完全本地的比例/尺寸模板 | 1:1、最长边 1080 | 提供透明构图起点；不冒充平台永久规范 |

老照片修复只保留为后续独立 AI 能力方向。当前没有划痕修复、面部恢复、生成式补全或上色模型，因此不在产品页显示为可运行场景。
