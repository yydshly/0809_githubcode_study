# Target Studio 电脑网页探测版设计契约

## 1. 进入与授权

```text
Entry mode: Revision-led / Build
Request revision: 6
Target user and context: 在电脑浏览器中研究“原图经过多种后台图片能力后，可以变成什么成品”的项目决策者
Desired first impression: 一眼看见系统提供的原图、可选成品目标和真实结果预览，而不是 Skill 列表或抽象流程
Visual ambition: Functional + Editorial
Experience architecture: Hybrid Workspace
Autonomy authorization: 用户明确要求“请开发”，允许在当前项目目录中直接实现和验证可逆的静态网页
User-decision boundary: 若要求网页直接调用真实 ImageGen 服务，将需要后端、认证与费用边界；未获授权前不接入真实外部服务
```

## 1.1 修订 3：完整结果、样例与生成引导

本轮由用户截图确认两个可见问题：中央成品在可视高度内被截断；“能力组合并生成”未能清晰区分能力编排、真实结果与导出。

```text
Entry mode: Revision-led / Repair + Build
Preserve: 三栏电脑工作台、四组系统原图、十二个目标与自定义目标
Primary journey: 选择一个系统样例 → 看懂输入与目标 → 查看将使用的能力 → 点击开始生成 → 中央完整显示结果 → 下载结果
Visual correction: 中央成品必须在可用画布内等比完整显示，上下左右边缘均可见；不再让成品高度溢出后被控制区截断
Information correction: “能力组合”只表示执行方案；“开始生成”才进入生成状态；完成后明确标记“结果已生成”与可下载文件
Sample guidance: 提供一条默认可直接体验的样例路径，并用“输入样例 / 目标样例 / 生成结果”说明关系
Real sample assets: 使用 ImageGen 生成四张项目内结果样例，作为真实视觉结果证据；非推荐目标仍使用 Canvas 生成可导出结果
Environment boundary: 仅电脑网页版；静态探测版不直接调用在线 ImageGen，实时外部生成仍属于后端、认证与费用边界
Observable completion: 1280×720 与 1440×900 下中央成品完整可见；生成前、生成中、完成后三态可区分；默认样例无需理解技能细节即可完成生成与下载
```

## 1.2 修订 4：目标优先的开放能力组合

用户进一步明确：Skill 不能成为互斥的风格或固定目标；产品应先接收开放目标，再按需组合 13 个 Skill 的能力、现有生成/合成/验证能力，并允许针对目标扩展新的能力。

```text
Entry mode: Revision-led / Product correction
Preserve: 电脑网页、完整结果适配、生成与导出状态、来源失败关闭
Remove from primary logic: 固定十二目标作为产品边界；单一 Skill 选择器；六张图拼成一个结果
Primary journey: 查看统一 SOURCE → 选择一个组合样例或输入任意产品目标 → 系统解释目标 → 组合多个 Skill 能力与本地基础能力 → 展示 SOURCE→RESULT → 生成并导出产品结果
Skill role: 后台能力来源与证据，不是用户必须理解的工具清单；每个被选能力必须说明来自哪个 Skill、解决目标中的哪个问题
Open target model: 预设只作为样例；用户可输入未预设的目标、用途、输出形态，系统按关键词和目标约束设计新的组合方案
Composition model: 事实提取 / 真实性契约 / 视觉转译 / 产品封装 / 确定性合成 / QA 六层，可在每层组合一个或多个 Skill 能力并加入本地扩展
Sample proof: 使用同一张全新 SOURCE 生成至少四种多 Skill 组合结果；每种结果显示参与的 Skill 与各自贡献
Observable completion: 首屏能看出“目标决定组合”；至少一个自定义目标可创建组合；结果不是原图拼版；中央同时可核对 SOURCE 和完整 RESULT；目标样例不是限制
```

## 1.3 修订 5：Codex 内置浏览器紧凑桌面布局

Codex 内置浏览器运行在电脑桌面应用中，但停靠面板可只有约 624px 宽。此前将“小于 1180px”直接判定为手机并隐藏产品，混淆了设备类型与窗口宽度。

```text
Entry mode: Repair-led / Responsive layout
Preserve: 电脑端鼠标键盘交互、开放目标、多 Skill 组合、完整 SOURCE→RESULT、生成与导出、1280px 三栏布局
Root cause: CSS 在 max-width:1179px 时隐藏整个应用，只显示“请使用电脑浏览器”
Compact desktop range: 480–1179px；用于 Codex 内置浏览器或窄桌面窗口，不代表手机 / 平板产品适配
Compact architecture: 顶部保留产品身份；目标输入、结果舞台、能力解释依次纵向排列；结果舞台优先于完整能力明细
Result requirement: SOURCE 与 RESULT 均完整显示；RESULT 仍是页面视觉焦点；不得产生水平滚动
Interaction requirement: 样例切换、自定义目标、能力组合生成、导出和来源失败状态保持可用
Standard desktop regression: 1180px 及以上继续使用三栏工作台，不改变既有主旅程
Observable completion: Codex 内置浏览器实际约 624px 宽时不再出现拦截页；默认结果可见且完整；主操作可达；页面无横向溢出；1280×720 三栏仍成立
Authorization: 用户明确说“继续”，授权完成该可逆前端修复与浏览器验证
```

## 1.4 修订 6：推荐优先，描述可选

用户指出首屏不应强制填写目标描述。目标文字应是个性化增强，而不是开始使用产品的门槛。

```text
Entry mode: Repair-led / Entry experience
Preserve: 当前统一 SOURCE、五条组合样例、开放目标、多 Skill 组合、完整结果、生成与下载
Observed problem: 首屏首先出现已填满的目标文本框和“根据目标设计能力组合”，使产品看起来要求用户先写需求单
Primary journey: 页面基于原图默认选中一个首选推荐 → 用户可直接采用、切换其他推荐并生成 → 只有需要个性化时才展开目标描述
Default recommendation: 周年记忆档案；同时露出材料化发布套件、参数化视觉指纹两个明显不同的替代方向
Optional input: 目标描述放入原生可展开区域，默认收起；空输入不报错，也不影响推荐、生成与下载
Copy correction: 用户主操作使用“推荐产品 / 使用当前推荐 / 根据描述推荐”等结果语言，不以“能力组合”作为开始门槛
State requirement: 推荐卡具有选中状态与可读理由；切换推荐立即更新中央结果、产物清单和后台能力说明
Responsive requirement: 705px Codex 紧凑桌面与 1280×720 三栏均可直接看到推荐入口；无横向溢出
Observable completion: 初次进入不需要输入文字即可完成推荐 → 生成 → 下载；展开自定义目标后仍能完成原有开放目标路径
Authorization: 用户直接提出应有行为，允许完成当前前端内的可逆交互修复
```

## 2. 用户要求对应关系

| 用户阶段 | 本次实现 |
| --- | --- |
| 第一：定制可选目标 | 提供五条可直接体验的组合样例，同时接受任意产品目标和主要输出形式；样例不是目标上限 |
| 第二：按目标组合后台技能并生成 | 从 13 个研究 Skill 中合并相关能力，加入本地生成 / 合成 / QA 和目标专用扩展；每层说明来源与作用 |
| 第三：系统提供 AI 原图 | 使用 ImageGen 全新生成一张雨夜自行车修理店 SOURCE；所有组合样例使用同一张图检验能力差异 |
| 第四：电脑网页探测 | 只验收桌面浏览器；不制作手机和平板布局 |
| 第五：不可控问题时提问 | 真实外部生成服务、认证、费用或无法恢复的来源错误才请求用户决定；普通界面实现自主完成 |

## 3. 混合工作区

```text
Persistent scene: 中央 Canvas 成品预览，贯穿选择、生成、完成与错误状态
Document/detail flow: 左侧原图和目标选择；右侧真实内容、能力组合、输出清单
Scene base: Canvas 2D
Scene persistence: 桌面视口内始终可见，左右栏独立滚动
Foreground control model: 顶部状态、左侧选择、中央生成与下载、右侧表单和组合状态
State-to-scene mapping: 初始预览 / 生成中 / 已完成 / 来源失败 / Canvas 不可用
Fallback: Canvas 不可用时仍显示目标、能力和输出清单；来源失败时禁止生成和下载并给出恢复说明
```

## 4. 视觉与信息方向

| 决策 | 选择 | 可观察约束 | 验收标准 |
| --- | --- | --- | --- |
| 构图 | 三栏桌面工作台 | 左侧 300–340 px，中间弹性画布，右侧 320–360 px | 1280×720 与 1440×900 不横向滚动，主结果保持可见 |
| 焦点 | 中央成品而非设置 | 画布面积最大，生成按钮唯一主操作 | 首次浏览能先识别原图到成品的关系 |
| 字体 | 中文无衬线操作界面 + 衬线成品标题 | 操作信息紧凑，成品预览有出版感 | 中文不截断，输入和状态清楚 |
| 色彩 | 深墨工作台、暖纸成品、雨蓝 / 琥珀 / 青绿来源色 | 颜色表达选择和状态，但不作为唯一信号 | 选中、生成、完成、错误均有文字状态 |
| 材质 | 轻边框、纸面和屏幕框架 | 不使用重玻璃拟态或装饰性渐变 | 容器边界和成品类型清楚 |
| 动效 | 仅生成步骤和轻微状态切换 | 尊重 reduced-motion | 关闭动效后信息和流程仍完整 |

## 5. 操作与状态约束

- 支持鼠标与键盘；所有按钮、输入、标签页和目标卡可聚焦。
- 目标入口分为“AI 推荐”“全部目标”“定制目标”。
- 原图入口提供陶艺工作室、风能机器人、实验音乐舞台、高山种子档案四个开放方向；每次切换都会重算推荐，不限定用户只能选择推荐项。
- 自定义目标成功创建后立即加入当前会话并被选中。
- 条件推荐和仅用户指定目标必须展示所缺真实信息；必填信息为空时禁止生成。
- 生成不是伪装的远程 AI 调用：当前探测版明确显示为“后台能力组合的确定性预演”。
- 点击生成后依次显示照片理解、路线规划、视觉生成、确定性合成与 QA 状态。
- 完成后可下载当前预览 PNG。
- 来源图加载失败时保持目标与能力说明可读，但禁用生成和下载。

## 6. 主旅程

1. 用户从四组系统提供的模型原图中选择一个题材方向。
2. 用户从 AI 推荐、全部目标或自定义目标中确定一个成品目标。
3. 用户选择原图增强、编辑拼贴或抽象材料三种改造方向。
4. 用户补充该目标所需的真实标题和用途信息。
5. 用户点击“组合能力并生成”。
6. 中央画布生成与目标形态匹配的结果，右侧同步显示能力组合完成状态。
7. 用户检查输出清单并下载 PNG 预览。

## 7. 环境边界

- 仅支持电脑网页版，浏览器实测视口为 1280×720 与 1440×900；更宽桌面由弹性中栏承接。
- 单一深色工作台主题；成品自身可以是明 / 暗纸面。
- 无依赖静态 HTML / CSS / JavaScript，通过项目现有静态服务器运行。
- 原图为本轮使用 ImageGen 全新生成的四组虚构安全样本；当前网页不上传用户文件，也不调用真实外部服务。
- 中文界面；不承诺其他语言与窄屏布局。

## 8. 可观察完成标准

- 三种目标入口均可操作，十二个预设目标均可选择。
- 自定义目标可以创建、选中并生成通用成品预览。
- 陶艺 / 工业 / 演出 / 自然档案四组原图会改变推荐目标、来源色和画布使用的照片。
- 至少十二种预设目标具有可区分的 Canvas 成品形态，而不是只换颜色。
- 三种改造方向会改变同一目标的视觉处理。
- 直接推荐目标可以完成生成和下载主旅程。
- 条件目标缺少必填信息时显示明确错误，补齐后可以生成。
- 来源缺失时 fail closed。
- 1280×720 和 1440×900 无横向滚动、遮挡或不可达操作。
- 键盘焦点可见，reduced-motion 下流程可用。
