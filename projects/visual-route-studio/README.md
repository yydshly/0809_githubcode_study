# Image Product Studio

> 一个图片优先的产品生成工作台：导入一张或一组图片，系统推荐适合的正式产品结构，随后组合图片理解、视觉生成、确定性合成与 QA 能力，交付可预览和下载的完整成品。

目录名继续使用 `visual-route-studio`，保留研究历史；当前电脑网页探测版工作名为 **Image Product Studio**。

> **方向状态更新（2026-08-12，Revision 17）**：上传新图后先选择一个可见的结果样例，中央在生成前展示参考效果；真实 AI 图片产生后再进入原图 / 参考 / 结果对比、结果库和产品适配。Canvas 不再冒充生成，13 个研究 Skill 只用于沉淀参考方法和生成配方。

## 当前产品探测

[Image Product Studio 电脑网页探测版](compositor/) 已实现：

- 上传新图后，六组主题按钮自动改为“参考效果入口”：点击只更换生成参考，不会再替换用户的新图。另有 8 种完整参考效果目录。
- 中央生成前只展示当前参考样例；真实生成后才解锁“结果”和“成品”，并提供原图 / 参考 / 结果三方对照与独立结果库。多个生成版本可以保留、切换和下载。
- 新增 `compositor/server.mjs` 本地安全服务：浏览器不接触密钥，服务端用用户来源图与最后一张参考图调用 GPT Image 编辑接口；未配置密钥时明确禁用生成，不再播放假动画或把 Canvas 当 AI 结果。
- 产品适配成为生成后的独立第四步：选中的 AI 图片进入主体主视觉、故事册、档案、轮播等结构；修改产品文字不会抹掉核心图片结果。
- 提供雨夜书店、陶艺工作室、风能机器人、实验音乐舞台、高山种子档案、雨夜修车铺六组一键样例输入，也支持从电脑选择 1–12 张 PNG、JPEG 或 WebP；素材仅在浏览器内读取。
- 明确区分三种处理单位：单图只交付一个成品；多图逐张为每张图片生成同一种独立产品；多图合集把图片组织成档案、故事或轮播等完整套件。
- 03 图片再创造方向与 04 成品用途继承 02 的选择：单图提供 8 种方向 / 5 个产品，逐张提供 6 种方向 / 5 个批次产品，合集提供 9 种方向 / 6 个合集产品；切换模式会自动清理不适用的旧选择。
- 左侧默认只纵向展示三个首选产品；弹窗只预览当前模式适用的 5 或 6 个产品，选择后会把它提升为新的首选并同步中央结果。
- 六组样例获得不同的默认首选：雨夜书店为图片故事册、陶艺工作室为视觉图鉴、风能机器人为展览信息板、实验音乐舞台为社交轮播组、高山种子档案为收藏档案卡、雨夜修车铺为主体主视觉。推荐区显示本次使用的 2–3 个信号，每张卡说明“为什么适合”；人工改选会明确标成“人工选择”。
- 产品推荐只回答“要做什么、会得到哪些文件”，不再把某个设计方向写成产品的固定属性，也不要求用户输入目标、选择 Skill 或填写描述。
- 产品推荐之前先纵向显示三个图片再创造首选；完整目录按当前处理单位展示 6–9 种方向。每张卡明确写出结果类型、“保留什么 / 重建什么”，人工改选会提升为首选并同步中央结果。
- 图片方向不再局限于滤镜和排版：新增实景编辑重构、结构拆解重组、场景想象重构、记忆重绘重生、多图场景融合与叙事续帧展开，并保留主体提炼、材料转译、证据编辑、关系抽象与视觉指纹等已有能力。
- “雨夜修车铺”单图已提供两张基于同一原图生成的真实对照结果：一张保留人物与蓝色自行车的手绘记忆重生，一张将同一现场拆解为钴蓝、橙色与黑色的结构化丝网印刷画面；它们不是在原图上叠加标题模板。
- 中央预览可在“原图 / 参考 / 结果 / 成品”之间切换；生成前只有原图与参考可用，真实 AI 结果产生后才开放结果和产品适配。图片处理强度只影响后续配方与适配，不会把旧 Canvas 预演冒充结果。
- 十一种正式产品结构：新增单图的主体主视觉、逐张的系列标准图、合集的视觉图鉴，并保留图片故事册、活动发布套件、明信片系列、编辑封面系统、收藏档案卡、社交轮播组、网页故事素材包和展览信息板。
- 合集右侧直接显示“输入原图 → 成品页数”和覆盖比例；每个交付文件标出使用的原图编号。六图样例中，档案卡为 4 页、轮播和网页故事为 5 页、故事册为 7 页、视觉图鉴为 8 页，全部覆盖 6 / 6 张原图。
- 保留原 StoryFold 简洁三栏并独立滚动：左侧素材、处理单位、图片处理和产品选择，中间持续显示完整成品，右侧显示当前模式真正交付的文件。
- 支持主图指定、处理单位切换、产品切换、文件切换、可选文字调整、生成状态、当前 PNG 下载和多文件 ZIP 下载。
- 当前只面向电脑网页；支持 1280px 标准三栏与约 620px Codex 窄桌面单列布局。
- 默认雨夜书店首先展示独立 4:5 参考效果；上传用户图片后，同一批主题按钮改为参考入口。预置结果只作为生成方法样例，不会进入用户的结果库。

设计契约见 [COMPOSITOR-CONTRACT.md](COMPOSITOR-CONTRACT.md)，浏览器证据见 [COMPOSITOR-VALIDATION.md](COMPOSITOR-VALIDATION.md)。

## 前序探索：Target Studio

[Target Studio](target-studio/) 保留“开放目标 → 多 Skill 组合 → SOURCE / RESULT”的前序研究成果。它证明了 Skill 可以按目标组合，但主界面技术解释较重、固定原图无法形成真实输入闭环，因此不再作为当前主入口。

## 历史纵向实验：StoryFold

Skill Zine Summary 已研究的 13 个图片 Skill 可以组成完整生产链：

> 照片理解 → 事实与关系提取 → 故事规划 → 原照 / 记忆 / 抽象 / 材料转译 → 图片生成 → 确定性拼版 → 产品封装 → QA。

StoryFold 不让用户逐个选择 Skill。用户只需要上传照片、说明故事、确认哪些图片必须原样保留，并从两套叙事方向中选一套：

- **现场叙事**：更多原照、地点、动作和事件连续性。
- **记忆叙事**：更多允许重绘的记忆页与关系抽象页。

系统随后按页面职责调用不同能力，并用统一颜色、mark、字体、留白和照片顺序把它们合成一套连续作品。

## 第一版六页结构

| 页 | 职责 | 成品特征 |
| ---: | --- | --- |
| 1 | 封面 | 一个故事命题、一个视觉锚点、真实标题 |
| 2 | 现场开场 | 完整原照与编辑色场 |
| 3 | 场景展开 | 2–3 张照片的连续拼贴 |
| 4 | 记忆转折 | 允许重绘的记忆图，或原照与 relic 并置 |
| 5 | 关系过场 | 从动作、方向、间隔和来源色提炼的 mark |
| 6 | 收束 | 结束语、日期 / 地点与纪念卡入口 |

详细能力映射见 [SKILL_COMPOSITION.md](SKILL_COMPOSITION.md)，完整产品契约见 [PRODUCT.md](PRODUCT.md)。

## 第一份受控样本

[雨停以前](samples/rainy-bookstore/README.md) 使用同一组六张合成照片，生成两套六页视觉概念：

- **现场叙事**保留更多原照、顺序和编辑摄影结构。
- **记忆叙事**保留照片证据，同时加入照片遗迹、手绘转译和关系 mark。

该样本验证了两套页面职责和共享视觉语言可以成立，但尚未证明像素级原照锁定、真实排字、独立页面导出或用户价值。

## 产品生成工作台

[电脑网页版工作台](compositor/) 在原确定性合成器上继续扩展：

- 默认 SOURCE contact sheet 仍被裁切为六张演示图片，旧故事册效果成为正式产品结构。
- 本地文件选择支持单图与多图，并根据素材数量更新推荐产品。
- 陶艺明信片、风能编辑封面、实验舞台发布套件与高山档案卡被归入可复用的产品结构，不再依赖孤立样例入口。
- 使用 Canvas 排版真实中文标题、说明、规格和文件编号；产品之间共享同一套简洁工作台。
- 当前可下载选中的 PNG，也可把整套产品打包为一个 ZIP；PDF、版本历史和单项重做仍属于后续生产能力。

当前只验收电脑网页版。完整实现范围见 [COMPOSITOR-CONTRACT.md](COMPOSITOR-CONTRACT.md)，浏览器证据见 [COMPOSITOR-VALIDATION.md](COMPOSITOR-VALIDATION.md)。

## 为什么保留确定性合成与 QA

研究中反复出现的“原照锁定、真实文字、页面结构和失败拒绝”不会成为另一个独立检查产品，而是 StoryFold 的生产底座：

- 生成模型负责无字视觉层。
- 原创合成器负责真实照片、文字、页码、比例和页面顺序。
- QA 只检查来源、结构、尺寸、文字和锁定区域等可明确判定的项目。
- 身份、故事事实、素材权利和审美判断仍由人负责。

## StoryFold 历史范围

首版只做一个固定而完整的产品：4–8 张照片 → 两套六页故事板 → 一套六页图片小志 + 封面 + 数字纪念卡。

首版不做通用设计代理、自由画布、任意页数、Skill 市场、模型选择器、自动事实推断或实体印刷承诺。

## StoryFold 历史结论

StoryFold 的核心不是“拥有很多 Skill”，而是让不同能力各自负责最合适的页面，并共同交付一个用户能保存、分享和继续使用的图片成品。

当前已经完成产品定义、第一份受控六页可视化样本和电脑网页版确定性合成器原型。SOURCE 裁切、真实文字、页码、来源 hash、错误拒绝和单页 PNG 生成已经可运行。下一阶段仍需接入无字生成层、页面版本 / 缓存与六页批量导出；用户研究继续后置。

## 本地运行

在仓库根目录配置服务端环境变量并启动图片工作台服务：

```powershell
$env:OPENAI_API_KEY = "你的服务端密钥"
node projects/visual-route-studio/compositor/server.mjs
```

打开 `http://127.0.0.1:4332/compositor/`。密钥只进入本地 Node 进程，不写入代码或浏览器存储；不要在对话、网页输入框或版本库中粘贴密钥。未配置时仍可完整体验参考选择和产品结构，但真实生成保持禁用。当前验证范围仅为电脑网页版；前序目标探索仍保留在 `http://127.0.0.1:4332/target-studio/`。

## GitHub Pages 公开逻辑演示

[公开地址](https://yydshly.github.io/0809_githubcode_study/visual-route-studio/compositor/)随仓库 `main` 通过既有 GitHub Pages workflow 发布。它包含内置样例、处理单位、图片方向、产品推荐、中央预览和结果结构，用于远端查看产品逻辑。

GitHub Pages 是纯静态托管，不运行 `compositor/server.mjs`，也不保存 `OPENAI_API_KEY`。因此公开版不会执行真实 AI 生成；生成按钮会明确保持未连接。需要验证真实生成时仍应使用上面的本地安全服务。
