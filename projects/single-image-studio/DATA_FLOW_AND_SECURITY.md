# 数据流与安全研究契约

> 文档角色：未来真实能力研究、R1-pipeline、R1-product、O1 与 G1 的数据和安全前置合同。本文不表示当前 R0 已实现加密存储、删除、访问控制或远程供应商治理；当前相关证据均为 0，状态以 [STATUS.md](STATUS.md) 为准。首轮客户端范围见 [QUALITY_AND_COMPATIBILITY.md](QUALITY_AND_COMPATIBILITY.md)，部署与恢复边界见 [DEPLOYMENT_RELEASE_AND_RECOVERY.md](DEPLOYMENT_RELEASE_AND_RECOVERY.md)。

## 1. 原则与范围

- 默认数据最小化：真实用户图片和所有可还原内容只为本次明确任务处理，不进入研究集、参考目录、训练、营销或长期日志。
- 处理同意、研究同意、公开展示许可和商业宣传许可相互独立；任何一项不能推出另一项。
- 图片、缩略图、Alpha、OCR 文本、Prompt、生成候选、EXIF、文件名、路径、可逆特征及可关联 hash 均按潜在个人数据处理。
- 远程模型、对象存储、队列、监控、内容安全或人工审核服务都是独立 processor 候选，必须逐项登记；不能用“云端”概括实际接收方。
- 本文先冻结合同，再实现和验证。没有证据时保持 G1=0，不把设计要求写成现状。
- 首轮邀请范围只声明 Windows 桌面 Chrome / Edge 的冻结精确版本；手机、平板、iPhone、Safari、Firefox、HEIC/HEIF 和完整响应式后置。客户端范围收窄不改变服务端上传、鉴权、隔离、删除、供应商和事故硬门，也不把用户电脑或浏览器当成可信安全边界。

## 2. 数据角色与处理方账本

每个部署版本必须登记实际法律角色和技术角色；下表只是逻辑位置，不代替适用地区的法律判断。

| 位置 | 默认职责 | 允许接收 | 禁止边界 |
| --- | --- | --- | --- |
| 浏览器 | 本地预检、hash、同意展示、上传与结果查看 | 用户主动选择的单图、本次会话状态 | 在同意前上传或做远程内容分析；保存到第三方埋点 |
| 第一方网关 | 鉴权、同意校验、规范化、路由、任务与删除编排 | 完成本次任务的最小字段和临时内容 | 把密钥、内部路径或其他用户资产返回浏览器 |
| 视觉 / 生成 worker | 执行冻结能力或配方 | 与该执行器合同相符的规范输入、mask、必要参考 | 读取无关账户、研究集或其他 run |
| 临时对象存储 / 缓存 | 以 run 和用户作用域保存临时资产 | 加密内容与最小索引 | 公共桶、永久 URL、跨用户 key 复用 |
| 远程模型 / 审核服务 | 只执行预先说明的外部处理 | 预检 allowlist 明确列出的字段和图片角色 | 未登记的二次处理、训练用途或静默转发 |
| 证据与安全日志 | 质量、可靠性、安全和删除证明 | 最小事件、不可逆或低关联标识、必要错误码 | 图片字节、缩略图、OCR 全文、Prompt 全文、EXIF/GPS、原文件名 |

部署前需要明确谁决定处理目的、谁作为 processor、数据可能经过的地区、供应商子处理方、联系人和合同版本。结论写入 `DataPolicy` 与供应商注册项。

## 3. 目标数据流

```text
本地文件选择
→ 浏览器仅做格式 / 大小预检与本地 hash
→ 展示实际处理方、目的、外发字段、保留与删除说明
→ 用户确认处理权与数据告知
→ TLS 上传到第一方网关
→ 隔离解码与恶意输入检查
→ EXIF 方向解析；提取最小必要字段；删除 GPS / 非必要元数据
→ 生成 NormalizedImage 与临时资产 ID
→ 依据冻结 allowlist 路由到本地或远程 processor
→ QA 与结果
→ 限时、用户 / run 绑定的签名下载
→ TTL、用户删除或任务终态触发清理
→ 只保留最小审计与删除证明
```

未经归一化和元数据清理的原始文件不得默认发送到远程模型。若某执行器确实需要原始元数据，必须把字段、原因、风险和 TTL 单列为新的合同版本并重新取得同意。

首轮不接受远程图片 URL。未来若增加 URL 导入，必须使用独立下载服务和出站 allowlist，禁止访问 localhost、私网、云元数据地址、非 HTTP(S) 协议和重定向到受限网段；限制 DNS 重绑定、响应大小、重定向次数、MIME 与解码像素。

## 4. 首轮桌面范围与威胁模型

### 4.1 信任边界与假设

每个部署版本必须把实际组件映射到以下边界并记录数据类别、协议、身份、owner 和地域：

```text
不可信本地文件 / 用户输入
→ 不可信浏览器运行环境
→ 公共网络
→ 第一方网关与控制平面
→ 队列 / worker / 临时对象存储
→ 远程模型、审核或其他 processor
→ 下载、支持、证据日志和备份边界
```

- 浏览器预检、UA、扩展名、客户端 hash、隐藏字段和按钮禁用都不是安全边界；网关重新验证授权、绑定、格式、配额和状态。
- 假设用户的 Windows、浏览器账户、扩展和本地文件系统未被恶意软件完全控制；本项目不能保护已被接管的终端，但仍不得把服务密钥、其他用户资产或长期下载凭据暴露到 DOM、bundle、缓存或浏览器日志。
- Chrome 与 Edge 同为 Chromium 不等于行为、策略和扩展环境相同。精确版本和安全 header 在 CompatibilityProfile / ReleaseManifest 中冻结；浏览器升级不自动继承 G1 或兼容证据。
- 首轮不接受远程图片 URL、剪贴板静默读取或目录上传。若未来增加，必须另建数据流和威胁模型版本。

### 4.2 威胁与控制

| 威胁 | 可能后果 | 首轮必需控制与验证 |
| --- | --- | --- |
| 伪造 / 篡改 / 重放请求 | 重复计费、错误任务或资产替换 | 会话、source revision、run、attempt、asset、幂等键和合同版本绑定；服务端状态机与重放测试 |
| 跨用户 / 跨 run 枚举 | 查看或下载他人图片 | 不可猜测 ID 不能替代鉴权；逐次关系校验、短期签名下载、IDOR 负面测试 |
| XSS、CSRF、恶意结果或元数据 | 操作会话、泄漏凭据、错误展示 | 输出编码、无 HTML 注入、受限 CSP、同源 / CORS allowlist、CSRF 防护、cookie 策略；图片 / OCR / 文件名一律作为数据 |
| 恶意图片、压缩炸弹或解析器漏洞 | 内存 / CPU 耗尽或执行器入侵 | 魔数 / MIME / 像素 / 帧 / 解码预算、隔离低权限解码、超时、补丁和攻击夹具 |
| HEIC 等后置格式或动画被误处理 | 错图、首帧丢失、绕过检查 | 浏览器提示与网关双重拒绝；不静默转码、不静默取首帧；拒绝事件留最小错误码 |
| Prompt / OCR / 参考图注入 | 越权工具调用、数据外发或参考泄漏 | 冻结模板、字段 schema / allowlist、无任意 URL / 工具选择、输出和参考泄漏 QA |
| 旧标签页、迟到响应、缓存或 N/N-1 混跑 | 旧结果覆盖新图、删除后复活 | build / schema 协商、来源绑定、tombstone 优先、`no-store` 或冻结缓存策略、跨版本 acceptance matrix |
| 签名 URL、Referer、浏览器缓存 / 历史泄漏 | 临时资产被转发或长期保存 | 短 TTL 与 scope、撤销、`Referrer-Policy`、响应缓存 / disposition 策略、泄漏演练；URL 不含敏感文件名 |
| 供应商、子处理方或模型 snapshot 漂移 | 未告知外发、留存变化、质量或成本失控 | 精确 processor snapshot、条款 / 地域 / TTL 监测、出站 allowlist、kill switch、合格 fallback 才能切换 |
| 日志、支持工具、分析或备份过度采集 | 形成长期图片副本或跨会话画像 | 字段 allowlist、作用域标识、日志抽样、访问审计、逐类 TTL、恢复时 tombstone reconciliation |
| 依赖、构建或部署制品被替换 | 恶意代码、密钥或数据泄漏 | 锁定依赖、制品 hash / provenance、秘密扫描、不可变 ReleaseManifest、回滚与 kill switch |
| 资源 / 费用滥用和拒绝服务 | 队列拥塞、供应商费用异常 | 文件 / 像素 / 并发 / 重试 / 成本硬上限、限流、队列背压、circuit breaker 与告警 |

首轮邀请发布前，以上每类威胁至少有一个正向控制用例和一个负向 / 故障注入用例。不能实施的控制必须标为 `unknown/no-go`，不能以“仅桌面端”豁免。

### 4.3 浏览器安全边界

- 正式研究和产品页面只经 HTTPS；设置并验证与实际资源、processor 和下载流一致的 CSP、CORS、Referrer-Policy、frame / embed、防 MIME 猜测和缓存策略。具体值绑定 ReleaseManifest，不能在文档中假装已经配置。
- 第三方分析、错误追踪、字体、CDN 和支持工具默认不得接收图片 URL、对象 key、原文件名、OCR / Prompt、完整路径或稳定跨用户 hash；新增第三方即新增 processor / subprocessor 审查。
- 浏览器内 preview、Canvas、Blob URL 和临时对象在换图、删除、退出和 TTL 时解除引用；这不替代服务器及浏览器自身缓存策略验证。
- unsupported browser / format 的提示不是鉴权或攻击防护。即使 UI 阻止，网关仍对直接请求执行全部校验；范围外访问不得进入首轮兼容和用户研究分母。

## 5. `DataPolicy` 最小字段

```text
data_policy_id + data_policy_version + effective_at
controller_or_decision_owner + processors + subprocessors
purpose + allowed_destinations + processing_regions
data_classes + per_class_ttl + deletion_triggers
delete_slo + backup_expiry + vendor_deletion_behavior
encryption_in_transit + encryption_at_rest
access_roles + audit_fields + audit_ttl
research_reuse_allowed=false + public_display_allowed=false
incident_contact + policy_text_version
```

- 未知字段写 `unknown` 并阻止 G1，不得用默认同意补齐。
- TTL 从资产创建或任务终态中预先定义的事件开始计算；不能等系统有空再清理。
- hash 不是天然匿名数据。只要可以跨 run、账户或来源关联，就要限定用途、加盐 / 作用域、访问与 TTL。
- 研究自有夹具使用独立 DataPolicy 和存储域，不能与真实用户临时资产混放。

## 6. 删除与后台任务

- 页面从上传完成起提供删除入口。删除请求立即撤销会话与签名下载，生成 tombstone，并在 `delete_slo` 内清理原图、规范图、Alpha、候选、失败、结果、缓存和队列 payload。
- `SUPERSEDED` 和 `DETACHED` 不是无限留存理由。可取消的任务立即取消；不可取消的远程任务在返回时只执行丢弃与清理，不回填页面。
- `UNKNOWN` 只在冻结查询窗口内保留恢复所需最小状态。窗口结束后转入待清理；用户显式删除优先于恢复，迟到结果命中 tombstone 后不得重新创建资产。
- 供应商不支持取消或删除时，上传前必须说明其实际保留边界；本地删除回执不得声称供应商已删除。若该边界与目标用户或任务风险不相容，该服务为 no-go。
- 备份和不可变安全日志可以有不同到期时间，但必须在告知中说明，限制访问，并不能包含可重建用户图片的内容。

## 7. 上传、解码与文件安全

- 浏览器预检只改善体验，不是安全边界；网关重新验证允许格式、声明 MIME、魔数、文件大小、像素数、帧数、色彩通道和解码后的内存上限。
- 客户端 hash 只用于预交互绑定和上传一致性提示；网关收到字节后重新计算服务端作用域 hash 并以其建立 source revision，不能信任客户端提交的 hash 作为资产身份或授权证明。
- 解码在低权限隔离进程中执行，设置 CPU、内存、时间和输出像素预算，防止压缩炸弹、超大 ICC / EXIF、畸形动画、多页文件和解析器漏洞拖垮服务。
- 文件名不参与磁盘路径；对象 key 由服务端生成。拒绝路径穿越、控制字符、双扩展名和依赖客户端 MIME 的行为。
- EXIF 方向只在受控解析后应用；GPS、设备序列号、注释、缩略图和非必要配置在任何远程外发前清理。需要保留的 ICC 只用于受控颜色转换，不原样转发。
- 原文件和每个派生资产分别计算作用域 hash；hash 用于一致性，不替代恶意内容扫描、授权或任务 QA。

## 8. 模型、OCR 与 Prompt 注入

- 图片、OCR 文本、EXIF、文件名和用户描述均视为不可信数据，不是系统指令。
- OCR 或模型观察只能写入有长度、类型和枚举限制的 `SourceCard` 字段；不得把图片中的“忽略规则”“调用工具”或 URL 拼进系统 Prompt、工具参数、日志查询或网络请求。
- 执行器使用冻结模板和字段 allowlist；模型输出不能自行选择新 processor、读取其他资产、改变保留策略或解锁下载。
- 参考图按明确角色传入并记录 hash；必须检查人物、品牌、文字、水印和其他参考内容泄漏。外部模型的 mask 遵从不等于像素锁定。
- 内容安全检查、拒绝类别、人工复核入口和申诉 / 错误恢复必须按服务与任务版本冻结；安全拒绝不能通过无上限重试规避。

## 9. 访问、传输与下载

- 真实用户研究与未来产品只允许 HTTPS/TLS；R0 局域网 HTTP 仅用合成或非敏感图，不取得 G1。
- 内容资产静态加密；密钥与数据分离，按环境和用途隔离。服务凭据只在服务端秘密存储中使用，不能进入浏览器、仓库、Prompt、错误响应或普通日志。
- 每个匿名会话或账户使用不可猜测、短期、作用域明确的访问凭据；服务端对每次资产读取重新验证用户 / 会话、run 和资产关系。
- 下载使用短期签名 URL 或等价授权响应，绑定当前用户 / 会话、当前 run、资产和允许的 disposition；撤销、删除、过期或换图后立即失效。
- 管理和人工复核遵循最小权限、显式工单理由和可审计访问；生产用户资产不出现在开发控制台、分析看板或普通错误追踪附件中。

## 10. 远程服务前置检查

任何图片或可还原特征外发前，逐个服务 / snapshot 完成并冻结：

1. 不可变模型 / API 版本、端点、供应商和子处理方；
2. 输入、输出、日志、审核副本的用途、地域、保留期和删除能力；
3. 是否用于训练、人工审核、滥用监测或产品改进，以及可用的退出方式；
4. 用户处理权、人物 / 商标 / 作品权利、供应商条款和输出用途边界；
5. 实际发送字段、图片角色、尺寸、元数据和最小化理由；
6. TLS、鉴权、密钥轮换、配额、限流、超时、重试、幂等和取消语义；
7. 安全拒绝、数据泄露、供应商事故和条款变化的通知 / 停用流程；
8. 成本、p50/p95、失败率和供应商副本无法删除时的 no-go 判定。

任一项为 `unknown` 时，不得使用真实用户图，也不得取得 G1。仅使用项目自有合成夹具做版本解析时，仍须避免上传未清权内容。

## 11. 限流、密钥与事故响应

- 限制每会话、来源、任务和服务的并发、请求次数、像素、候选数、重试与成本；服务端硬上限不能由浏览器覆盖。
- 只对冻结的瞬时错误有限重试；安全拒绝、格式错误、权利拒绝和确定性 QA 失败不自动重试。
- 密钥按环境和供应商分离，使用最小权限、轮换和撤销；异常费用、429/5xx、访问模式和下载枚举进入脱敏告警。
- 事故计划至少覆盖误发给错误 processor、跨用户结果、公开对象、日志泄漏、恶意解码、密钥暴露、删除失败、供应商条款突变和迟到结果复活。
- 事故发生后先停止相关入口和外发，保护证据、评估影响、轮换凭据、通知责任人和必要用户，再以新版本修复。不得为了保留调试材料而无限期保留受影响用户图片。

## 12. 证据与退出条件

取得 G1 前至少需要：

- 一张与部署一致的数据流图和 processor / subprocessor 清单；
- 一份与精确 ReleaseManifest / CompatibilityProfile 一致的威胁模型、信任边界、控制 owner 和剩余风险记录；
- 冻结 DataPolicy、用户告知和同意文案版本；
- 在目标 Chrome / Edge 精确版本和服务端直接请求层完成上传攻击、跨用户访问、XSS / CSRF / CORS / CSP、安全 header、签名下载、Prompt 注入、限流和秘密泄漏测试；
- 对 JPEG / PNG / WebP 候选、HEIC/HEIF 与其他后置格式、动画 / 多页、畸形 ICC / EXIF 和压缩炸弹完成允许或安全拒绝矩阵；
- 成功、失败、`SUPERSEDED`、`DETACHED`、`UNKNOWN`、用户删除、缓存和备份到期的删除演练；
- 完成 N/N-1、旧标签页、迟到结果、备份恢复与 tombstone reconciliation 的跨版本演练，证明删除资产不会复活；
- 远程服务前置检查与条款变更停用演练；
- 日志抽样证明不含图片、缩略图、OCR / Prompt 全文、EXIF/GPS、原文件名或内部秘密；
- 一次事故桌面演练及责任人、响应时限和复盘记录。

这些检查通过前，真实用户研究只能使用满足研究协议和风险边界的受控环境；R0 工程探针不能承接敏感真人、证件、医疗、未成年人或其他高风险图片。
