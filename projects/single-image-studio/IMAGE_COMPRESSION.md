# 图片压缩体验契约

状态：内部产品 Alpha；用户已提供旧工具作为参考，并授权直接集成到当前项目。

## 设计契约

- Entry mode：revision-led feature implementation。
- Request revision：4；旧 HTML 只说明“图片过大需要处理”的问题场景，不是版式、9:16 或参数设计规范；用户观察到默认降到 2048px 导致压缩率过高，因此默认改为先保留原图像素；随后要求解释压缩幅度对画质的真实影响，因此结果页必须把文件体积、像素保留和 JPEG 质量分开说明。
- Target user：图片文件过大，需要更容易上传、发送或保存，但不想学习编码参数的普通用户。
- Desired first impression：先说明接收方允许的文件上限，再由系统自动处理，不要求用户猜测 JPEG 参数。
- Visual ambition：Functional。
- Experience architecture：Editorial Flow。
- Primary journey：上传并确认图片 → 选择“图片压缩” → 设置接收方允许的目标大小和可选最长边 → 系统逐级生成真实 JPEG → 明确显示达标 / 未达标 → 对比完整原图与结果 → 下载。
- Autonomy authorization：用户明确要求实现该能力，可直接做可逆的本地产品改动。
- User-decision boundary：不自动覆盖原图；用户决定目标体积与可选最长边；结果若没有达标，必须明确提示而不是把“生成了文件”伪装成成功。

## 产品边界

- 图片只在浏览器本地解码、缩放和编码，不上传远程服务。
- 保持完整原图比例，不因为旧参考页面或社交平台比例而裁切、拉伸、补白或强制 9:16。
- 输出 JPEG；带透明像素的 PNG / WebP 会使用用户可见的底色填充，因为 JPEG 不支持透明。
- 压缩会改变像素尺寸或 JPEG 编码质量，属于有损处理；原图保持不变。
- 默认“不放大”：原图小于最长边上限时保持其像素尺寸；最长边默认取原图实际最长边，可在 320–8192 px 内设置。
- 输出同时受 1600 万像素安全上限约束；超大原图会按比例缩到该上限内，避免浏览器画布失控。目标是通用分享和上传，不是印刷母版或档案保存。
- 文件体积取决于画面复杂度，不能仅根据质量百分比准确预估。系统必须真实编码、重开并核对结果，找到首个达标档位才可声称达标。
- 未达标必须明确显示，不能因为文件比原图更小就把它描述成满足接收方限制。
- 原图已经满足目标上限时停止操作，提示用户直接使用原图，避免不必要的有损处理。
- “体积减少 80%”不等于“画质下降 80%”。设置页只说明达到目标至少需要减少多少体积；结果页依据实际输出分别显示文件体积变化、原图/结果尺寸、像素保留比例、JPEG 质量和预计影响等级。影响等级只是参数风险提示，最终仍由用户通过原图/结果对比确认。

## 目标场景

| 场景 | 目标体积 | 适用情况 |
| --- | ---: | --- |
| 普通上传 | ≤ 2 MB | 常见网站、社交与普通表单上传 |
| 严格上传 | ≤ 1 MB | 对附件上限较严格的表单 |
| 小附件 | ≤ 500 KB | 邮件、聊天或低带宽传输 |

用户可以在 100–10240 KB 内填写自定义目标，并在 320–8192 px 内设置最长边上限。系统先保持当前最长边，只把 JPEG 质量从 90% 调到 82%；仍不达标才开始按原图最长边比例逐级缩小，最低到 40% / 640 px（若用户上限更低则尊重其上限）。首个达标结果即停止。这里的“自动”是确定性的逐级编码，不是模型推断。

## 接受标准与覆盖

| 路径 / 状态 | 验收标准 | 证据 |
| --- | --- | --- |
| 任务入口 | 明确“本地、保持比例、输出 JPEG、不会覆盖原图” | DOM / 文案测试 |
| 默认设置 | 默认目标不超过 2 MB，完整原比例且不放大 | 状态 / renderer 测试 |
| 手动设置 | 目标 KB 与最长边均有边界、可键盘操作、数值可见 | 单元测试 + 浏览器操作 |
| 真实结果 | 结果来自共享 renderer，并完成格式、尺寸、像素和哈希重开检查 | renderer / output validation |
| 大小反馈 | 显示原图、目标与结果大小、达标状态、实际尺寸 / 质量和尝试次数；不伪造达标 | 单元测试 + 结果页观察 |
| 画质解释 | 将体积减少、像素保留与 JPEG 质量分开显示，给出预计轻微 / 一定 / 明显影响，并引导并排检查细节 | 单元测试 + DOM / 结果页观察 |
| 透明输入 | 明确 JPEG 底色逻辑，底色控件可见 | DOM / renderer 测试 |
| 下载 | 文件名为 compressed-image 前缀且与当前任务结果绑定 | download contract 测试 |
| 窄屏 | 复用当前任务配置与完整图片结果布局，不新增横向溢出 | 浏览器观察 |

## 明确不做

- 不批量压缩多张图片。
- 不声称精确等于某个 KB / MB；只判断真实结果是否小于等于用户上限。
- 不提供无损 PNG 优化、AVIF / WebP 转码或元数据保留承诺。
- 不把视觉预览当作文件大小结果；必须实际生成后再报告。
