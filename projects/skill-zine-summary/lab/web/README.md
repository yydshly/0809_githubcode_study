# Zine Skill 能力研究站

面向 13 个 Zine Skill 的本地多页面研究站。每个 Skill 都是一项独立研究目标，页面包含：能力描述、适用场景、固定提交的上游 Demo、我们的统一场景扩展实验、已经兑现的独立计划、每张效果对应的完整应用场景、技术路径、能力边界、验收清单、相近路线、扩展方向与仍待回答的下一轮问题。

## 研究导航

- [研究总索引](../../RESEARCH-INDEX.md)：统一说明网页与 Markdown 的关系、证据等级、阅读路径和发布边界；
- [本地研究入口 `/research`](http://localhost:4317/research)：浏览 Skill 选择器、13 个 Skill、比较页、实验室和报告入口；
- [公开新人学习入口](https://yydshly.github.io/0809_githubcode_study/start/)：与样例图库分离，先理解路线、输入、失败、证据等级和第一次实验；
- [Skill 选择器 `/choose`](http://localhost:4317/choose)：从任务用途、真实性、技术路径和产品化形态反选 Skill，并直达对应证据；
- [多原图实验室 `/labs/multi-source`](http://localhost:4317/labs/multi-source)：集中查看不同原图在各 Skill 下的完整 SOURCE → EFFECT 证据；
- [Revision 10 独立原图扩样](REVISION10-INDEPENDENT-SOURCES.md)：核对第一轮 13 张独立 SOURCE、对应 EFFECT、用途与生产边界；
- [Revision 11 反向题材与产品预演](REVISION11-STRESS-AND-APPLICATIONS.md)：核对第二轮 13 个相反角度、产品载体、环境语境与生产下一步；
- [Revision 12 完整产品系统](REVISION12-PRODUCT-SYSTEMS.md)：核对第三轮 13 个新题材如何进入多表面产品、使用环境和四步生产路径；
- [Revision 13 Skill 选型](REVISION13-SKILL-CHOOSER.md)：核对 `/choose` 的四维筛选、13 Skill 证据映射和不可排名边界。

## 页面结构

当前共有 7 类核心 Web 入口：

- `/research`：网页、Markdown、证据等级和推荐阅读路径的统一研究入口；
- `/choose`：按用途、真实性、技术路径和产品化形态从任务反选 Skill，并关联具体 SOURCE → EFFECT；
- `/`：13 个独立研究目标的目录；
- `/comparison`：同一张合成原图驱动全部 Skill 的受控横评；
- `/labs/multi-source`：按 Skill 汇集现有多原图 SOURCE → EFFECT 证据、场景与边界；
- `/reports/revision-7`：7 张来源、12 个 Skill、24 组跨题材实验的可浏览结论报告；
- `/skills/<slug>`：单个 Skill 的完整研究页，共 13 个路由。

Revision 7 报告路由和全部内容继续保留；主导航把原来的 R7 位置交给更常用的 `/choose`，R7 仍从 `/research`、单 Skill 页和 Markdown 文档地图进入。`/research` 同时索引 20 份核心 Markdown 文档。

`/labs/multi-source` 当前聚合 127 组图片 SOURCE → 图片 EFFECT：13 组 Revision 12 产品系统实验、13 组 Revision 11 反向题材压力测试、13 组 Revision 10 独立原图扩样、37 组统一湖岸基线、20 组图片计划交付、4 组 Photo Relic 受控配对和 27 组跨题材探索。它们来自 57 个不同图片来源路径；页面会同时显示两个数字，避免把重复来源说成 127 张独立原图。2 个文字驱动静态效果和 2 个实时交互不计入图片配对，但纳入 129 个静态／131 个总效果证据的披露。为控制本地研究资产体积，页面一次只展开一个 Skill，其余 Skill 只显示文字数量入口。

Revision 10 不再复用七张来源继续扩大效果数，而是给全部 13 个 Skill 各补一张不复用的新输入。题材覆盖故事人物、多人协作、动作、静物、建筑、自然、夜景、旅行产品与代码原生关系图；对应效果依据各 Skill 的公开高层规则制作，仍明确标注为本地概念研究，不冒充上游实际运行。完整方法、逐项用途和资产路径见 [REVISION10-INDEPENDENT-SOURCES.md](REVISION10-INDEPENDENT-SOURCES.md)。

Revision 11 再为全部 13 个 Skill 各增加一张与上一轮在人物依赖、密度、光线、空间或运动方式上相反的 SOURCE，并把同一 EFFECT 放入产品画布和使用环境的 HTML/CSS 数字预演。13 个预演不重复计为新效果，也不代表实体印刷、客户项目或现场投放；完整矩阵见 [REVISION11-STRESS-AND-APPLICATIONS.md](REVISION11-STRESS-AND-APPLICATIONS.md)。

Revision 12 为全部 13 个 Skill 再增加一个新题材，并把“可能用于某个场景”推进为完整产品系统：每组至少画出三种产品表面、一个使用环境、四步生产路径、输出规格、受众和边界。产品系统始终复用对应 EFFECT，不重复计为新效果；完整矩阵见 [REVISION12-PRODUCT-SYSTEMS.md](REVISION12-PRODUCT-SYSTEMS.md)。

Revision 13 新增 `/choose`，把现有证据按用途、真实性、技术路径和产品化形态重新组织为任务选型入口。它不新增 SOURCE、EFFECT、产品系统或效果证据，也不把图片数量、成熟度标签或筛选命中换算为质量排名；完整契约见 [REVISION13-SKILL-CHOOSER.md](REVISION13-SKILL-CHOOSER.md)。因此 127 组图片配对、57 个来源路径、129 个静态效果、131 个总效果证据和 13 个 R12 产品系统的口径保持不变。

研究顺序是“上游证据 → 能力拆解 → 我们的场景迁移 → 边界验收 → 后续扩展”。上游图片证明原项目展示过什么；统一原图实验用于检查能力是否可以迁移。两类图片不混作质量排名。

每个详情页提供页内章节导航和两个相近 Skill 入口，方便对照视觉相似但真实性契约或执行后端不同的路线。`public/og.png` 是研究站自己的原创分享预览图，不含上游样例。

首页正文现在也直接展示这张研究站封面，不再只把它藏在分享元数据中。上游素材充足的研究页已扩充为 4–6 张固定提交样例；`daily-photo-playground` 和 `pixel-style-poster` 的上游现有可用样例只有 3 张，页面会明确标注“已全部展示”，不会复制图片凑数。为保持研究密度，每个详情页现在至少展示 6 份可见证据；上游样例不足时，通过明确标注的“我们的扩展实验”补足，而不是伪造上游案例。

全站图片统一采用完整画幅展示：保持原始宽高比，以留边适配不同容器，不使用 `cover` 裁切。这个约束同时覆盖首页主图、研究卡片缩略图、研究站封面、上游 Demo、我们的扩展实验和统一横评页。

研究图现在都可进入沉浸查看：点击图片或用键盘聚焦后按 Enter/Space，即可在全屏暗场中完整查看；左右按钮或方向键切换相邻证据，Escape、关闭按钮或暗场空白处返回原页面。查看器保留图片说明、证据标签与“打开完整原图”入口，并在关闭后把焦点还给原来的图片。

Revision 6 把研究重点从“继续增加验收细节”转向“单个 Skill 如何形成真实产品”。13 个详情页现在各有 2 个与自身能力匹配的产品应用，共 26 个场景；每个场景依次展示完整 Skill 效果、可直接阅读的完整产品版面、产品进入现实环境后的数字预演，以及“保留 → 适配 → 生产 → 应用”四步处理链。产品类型覆盖编辑出版物、海报、移动端、展览、数字界面、包装、教育材料和档案系统；26 个案例进一步各自声明独立产品呈现，不会把三封面套组、八折册、互动墙、四季档案墙、包装纸或明信片继续塞进同一个通用外壳。每个成品会按照真实交付列出并画出 3–8 个表面。环境图是明确标注的数字预演，不冒充真实印刷、投放、部署或客户项目照片。

Revision 7 把“跨题材能力探索”扩展到其余 12 个页面。它复用 7 张项目内合成来源，向 12 个 Skill 各提出 2 个不同的能力问题，共形成 24 组实验、24 张新效果 PNG、24 张网页研究卡和 24 个轻量 HTML/CSS 产品语境预演。这里的“24 组”不是 24 张不同来源照片；来源跨 Skill 复用，用来观察相同人物、建筑或物件在不同信息选择语法中的变化。`photo-distill` 的人物、复杂城市和四季系列 3 组来自 Revision 6，本轮没有为它新增效果，也不计入这 24 组。

每组 Revision 7 卡片都成对展示完整 SOURCE 与完整 EFFECT，并说明保留了什么、结果中没有保留什么、结论状态、证明与未证明事项，以及进入真实生产仍需的处理。产品语境预演复用同一张效果图，不是额外生成图片、实体成品、客户项目或现场部署。24 张效果是图像模型依据本地来源和我们对 Skill 规则的理解生成的概念性研究，不是实际运行上游 Skill 得到的原生输出。浏览器可直接进入 `/reports/revision-7` 阅读 12 个 Skill 的 24 组结论；完整文档见 [REVISION7-RESEARCH.md](REVISION7-RESEARCH.md)，资产指纹与真实性边界见 [REVISION7-ASSETS.md](REVISION7-ASSETS.md)。

Revision 12 后，全站共有 129 张完整静态效果和 2 个 Photo Distill 实时实验，即 131 项本地效果证据。Revision 10、11、12 分别给 13 个 Skill 各增加 1 张独立来源效果；R12 另为每个新效果增加完整产品系统，但这些产品表面与环境均复用同一 EFFECT，不纳入效果计数。Revision 6 的 26 个完整产品场景、Revision 7 的 24 个轻量预演、Revision 11 的 13 个压力测试预演与 Revision 12 的 13 个产品系统均按各自证据层说明，不冒充实体产品案例。

Revision 3–5 的计划实验会保留并展示原计划原文，再给出实验问题、完整输入、完整效果、来源事实、方法配方、逐项 PASS/QUALIFIED 结论、真实任务、目标使用者、可形成的交付物、适配理由、扩展方向与使用边界。Revision 7 的跨题材卡使用较轻的数据结构，重点记录能力问题、保留/删除、产品方向、三步处理和产品语境，不冒充前述完整计划验收。Pixel 页面同时保留第一次全身人物阶段尝试与真正头肩大近景补证；Poetic 用源图 SHA-256 证明此前确定性实验的照片窗原字节嵌入；Photo Abstract 以 8／8 mark 固定此前两条路线的预算；Photo Distill 则把当前 SVG 真正绘制到 300×400 Canvas，对 120,000 个像素计算实际着墨率。上述确定性结论不自动转移到 Revision 7 的生成式概念图。

Revision 5 当轮的跨页面实验覆盖低饱和雨景、五 mark 单人动作、夜景高反差的三档浅面板、四季同地点系列、空旷雪地三角色、同主题等预算三变体、单一静物的两处记忆细节、当前浏览器渲染指纹和三张旅行明信片套系；当时新增 4 个合成 PNG 输入／效果与 9 个可重建、自包含 SVG。Revision 7 则新增 24 张 `1024 × 1536` PNG 效果，没有新增上述 SVG。图像生成、确定性组合与代码原生路线会分别标明真实性边界；需要原照像素锁定的概念图不会被描述为已经通过像素验证。

`photo-distill` 的参数页不是界面截图：三个滑杆实时改变 SVG 主线宽、三圆锚点总面积和缩略主锚直径，并用本研究自定义阈值产生 PASS/ADJUST。前三项指标来自 600×800 SVG 几何计算；第四项会把当前完整 SVG 绘制到 300×400 Canvas，逐像素统计相对暖纸底色的实际着墨覆盖率。“超限示例”会越过本研究 5% 的着墨上限并显示 RASTER INK FAIL。第二个实时实验还会等待字体就绪，把固定 SVG 栅格化为 300×400 Canvas，计算 SVG SHA-256、像素 SHA-256、120,000 像素着墨率和当前引擎；未实际运行的 Firefox／WebKit 明确显示 `UNAVAILABLE`。浏览器、字体和抗锯齿可能影响结果，因此跨浏览器问题仍保持开放，也不冒充上游官方标准。

`photo-relic-editorial` 已完成一轮独立补充：三组虚构北港同城建筑，以及一组“末班车之前”的成年女性叙事场景。每组都成对展示“生成输入图”和“我们的研究效果”，并列出来源事实、主 relic、固定配方与验收点。人物示例采用虚构成年人，不对应真实公众人物；强调人物姿态、丰富服装色彩、雨夜环境与故事线索之间的关系，不以面孔或身体作为孤立卖点。

```

```

## 图片与发布边界

`public/generated/` 包含上游研究样例和本地生成结果，继续被 Git 忽略，避免进入公开源码仓库。完整研究站经用户确认后通过独立托管公开展示：65 张可映射到固定提交的上游样例直接引用原仓库文件，3 张目录来源样例随站点打包；本地 SOURCE/EFFECT 由独立站点提供。页面必须保留上游仓库、固定提交、许可判断与“本地研究并非上游官方输出”的说明。部分上游没有正式许可证，`travel-photo-abstraction` 还带有修改与再分发限制；公开访问不扩大原许可，也不代表素材可被访问者继续复用。

GitHub Pages 继续只发布不含完整样例图库的轻量指南；完整图像研究站使用独立部署，避免将约 590 MB 研究资产写入公开 Git 历史。后续若更换、下载或再利用上游素材，仍需回到 `UPSTREAM.md` 与原仓库核对许可。

独立托管构建会在 `dist/` 内运行 `npm run optimize:sites-assets`：只压缩部署副本中的 PNG，保持文件名、像素尺寸和完整画幅不变；`public/generated/` 下的本地研究原件不会被修改。
