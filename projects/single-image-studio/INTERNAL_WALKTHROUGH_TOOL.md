# 内部体验走查台

状态：`tool-ready / browser-qa=2/2 / human-sessions=0`

[内部体验走查台](web/internal-walkthrough.html)把现有纸面协议变成一个可执行的主持工具。它不处理图片、不调用 Provider，也不替参与者点击产品；它只引导主持人完成告知、两个固定任务的观察和匿名 JSON 导出。样例、错误参考、自动回归和本工具统一从[内部质量入口](web/quality-hub.html)进入，并受[页面与能力注册规则](PAGE_AND_CAPABILITY_REGISTRY.md)约束。

## 为什么需要它

自动测试已经能证明按钮、状态和下载合同按代码运行，但不能回答第一次使用的人是否找得到入口、看得懂设置、理解错误或愿意保留结果。走查台用最小记录把这类问题显式化，同时避免为了“做用户研究”而收集姓名、联系方式或参与者照片。

## 固定方法演练

首轮只安排 2–3 人，用于发现明显的主持、任务或界面理解问题。每人按顺序完成：

1. **基础编辑与下载**：项目合成演示图 → 1:1 → 顺时针 90° → PNG 下载；
2. **隐私友好分享副本**：项目合成演示图 → 日常分享预设 → JPEG 下载 → 复述能力边界。

第二项重点不是“是否会压缩”，而是参与者能否分清：输出会清理受控文件 metadata，但不会识别人脸、地址、车牌、二维码、水印或画面文字。

2–3 人方法演练不满足 [M2_INTERNAL_WALKTHROUGH.md](M2_INTERNAL_WALKTHROUGH.md) 的 `5–8` 人分母，也没有 80% 通过判定。只有任务脚本和主持方法稳定后，才决定是否按 M2 扩到 5–8 人。

## 数据边界

走查台只允许导出：

- `IW-` 匿名场次编号；
- build commit、浏览器和视口；
- 开始 / 完成 UTC；
- 两项任务的结果、时长、求助、入口、下载、边界理解、信心和受限问题码；
- 最多 240 / 300 字的可复现页面观察。

记录 schema 拒绝未知字段、任务重复 / 换序、缺少同意、非项目图片声明，以及明显的邮箱或手机号码。页面不提供文件上传，不使用 localStorage / IndexedDB，不把记录自动发送到服务端。主持人点击“下载匿名 JSON”后，文件只进入当前浏览器的下载流程。

## 浏览器 QA 与真人结果分离

自动验收页是 [internal-walkthrough-acceptance.html](web/internal-walkthrough-acceptance.html)。2026-08-18 的 run `e4a3e486-9011-42d3-b376-778899aabbcc` 在 1180 px 和 390 px 以 `2/2` 通过，检查 13 项页面关系与路由可访问性、内部质量入口、同意门、两任务顺序、匿名 JSON、本地多记录汇总、清空上一场与无横向溢出。

该报告只保存在 loopback 服务内存中，版本为 `walkthrough-acceptance-report-v1`。它不是参与者记录，不能增加 `human-sessions` 或 M2 分母。

## 实际执行

1. 运行 `npm start`；
2. 主持人打开 `http://127.0.0.1:4177/internal-walkthrough.html`；
3. 参与者在新标签打开工作室，只使用页面合成演示图；
4. 主持人保持安静，按真实观察填写；
5. 每场导出一个匿名 JSON，先人工检查无身份信息，再放入受控工作记录；
6. 在[本地走查汇总页](web/internal-walkthrough-summary.html)选择 1–8 份记录；它会拒绝重复场次，按 build 分组，只输出计数和问题类别；
7. 2–3 人完成后只汇总界面问题，不宣布产品通过。

汇总页不会上传或保存原始 JSON，也不会把场次编号、`boundedNote` 或 `overallNote` 写入汇总文件。不同 build 的记录会显示警告，不能被静默合成同一个成功率。

真实场次开始后若改变任务原文、关键页面流程或记录字段，应停止合并旧新结果，并分别记录适用 build。
