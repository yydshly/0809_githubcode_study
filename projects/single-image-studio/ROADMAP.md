# 路线图

## 当前坐标：R0 工程探针

项目目前只有一套可运行的开发探针：上传、部分本地处理、服务调用边界、状态保护和下载路径已有代码与自动检查。这些成果用于降低后续研究成本，但不等于能力、结果或产品已经验证。

当前不声明 C1、U1、E1、R1-pipeline、R1-product、O1、G1 或 V1，也不以现有页面作为未来产品 UI 的视觉或信息架构约束。

首轮产品范围只包含冻结的 Windows 桌面 Chromium 环境。Chrome / Edge 精确版本、`1280 × 720` 与 `1440 × 900` 视口、键盘 / 鼠标 / 缩放范围由 CompatibilityProfile 冻结；手机、平板、Safari、Firefox、iPhone / HEIC 与完整响应式产品均在邀请 beta 之后另立范围。

路线图按证据依赖推进，不再设置“全部能力必须同时通过”的旧 Stage 门槛。不同能力可以独立停留、淘汰或继续；只有用户可见任务需要在进入产品前取得自己的完整证据。

## 波次 1 · 研究基础与互斥夹具集合

目标：让每次能力实验可复验、可比较、可审计。

- 按 [CAPABILITY_MAP.md](CAPABILITY_MAP.md) 建立 `CAP-01`～`CAP-09` 能力注册、适配接口、任务契约和统一运行记录，不创建另一套平行能力编号。
- 建立 `dev/calibration`、`holdout`、`defect`、`escape` 四套互斥集合。
- 在每套集合的 manifest 中标记 `NORMALIZE-DELIVER`、`MATTE-GT`、`MATTE-REAL`、`NATURAL-DEGRADE`、`CREATIVE-COVERAGE` 等 fixture suite；suite 是题材 / 任务维度，不是第五套集合，目录允许按新能力扩展。
- 按内容来源隔离集合；同图、近重复图、同一拍摄序列和同源衍生版本不得跨集合。
- 为每个输入分别建立 `ImageAsset` manifest 与 `SourceCard`：前者记录来源、许可、人物 / 品牌状态、处理 / 展示权限、hash 与敏感点，后者只记录可观察图片事实、置信度与 `unknown`，不得混成一份记录。
- 分开保存校准集和正式分母；正式运行前冻结指标、拒绝条件、灾难性失败和尝试预算。
- 为第三方代码、权重、服务和素材记录精确版本、上游地址、许可证与本地修改边界。
- 按 [MARKET_LANDSCAPE.md](MARKET_LANDSCAPE.md) 的统一字段登记优先产品流程、失败 / 拒绝、隐私、价格 / 时延和交付；当前缺口保持 `pending-source`，不从几个产品首页推导市场结论。
- 冻结 [SYSTEM_ARCHITECTURE.md](SYSTEM_ARCHITECTURE.md)、[OBSERVABILITY_AND_OPERATIONS.md](OBSERVABILITY_AND_OPERATIONS.md)、[QUALITY_AND_COMPATIBILITY.md](QUALITY_AND_COMPATIBILITY.md) 与 [DEPLOYMENT_RELEASE_AND_RECOVERY.md](DEPLOYMENT_RELEASE_AND_RECOVERY.md) 的逻辑合同；本波只建立 schema、profile 和测试入口，不虚构实现。

完成标志：四套互斥集合、各 suite 的分配和记录 schema 可以被独立检查；尚不要求任何能力达标，也不开发产品页面。

## 波次 2 · 主体 / 背景纵深

目标：先取得第一项可靠的可复用图片底座。

- 用同一接口对测开源与托管的检测、分割和 Alpha Matting 候选。
- 先在 `MATTE-GT` / `MATTE-REAL` suite 的 `dev/calibration` 上校准，再以不同来源的独立 `holdout` 测 Alpha、前景、边界、重复性、困难类别、色边、孔洞和灾难性误删；`defect` 验证坏结果会被 QA 拒绝。
- 选择通过的版本化管线，保留不通过方案的失败记录与淘汰理由。
- 固定 `normalize → detect → segment → matte → edge-refine / decontaminate → 黑白彩底预检 → 可选 correction revision → render → export → 重开文件 / hash → 最终 QA`；首轮结果与人工修正结果分开报告。
- 用同一版本化 Alpha / Foreground 产物产生透明 PNG 与纯色背景；纯色合成锁住安全前景像素，正式交付由独立 `DeliveryArtifact` 表示。
- 跑通成功、正确拒绝、可重试错误和不可重试失败的无界面任务路径。

证据目标：分割 / Matting 原子能力取得 C1；透明主体与纯色换底分别争取 U1。某个用户效果未通过时只隐藏该效果，不用生成式背景或页面包装掩盖失败。

## 波次 3 · 自然增强与 CR1 / CR2

这三个研究对象共享记录、QA 和运行设施，但证据互不替代。

### 自然增强

- 在 `NATURAL-DEGRADE` 上先跑确定性基线，再比较学习型方案。
- 只处理曝光、白平衡、对比、色彩、噪声、轻度模糊和适度锐化。
- 检查退化是否被真实改善，以及人物、物件、文字、颜色锚、几何和裁切是否保持。
- 将会生成新细节的超分辨率、人脸恢复和旧照修复保留为 `CAP-06` 下独立的重建型效果，不混进“自然增强”的 U1。

证据目标：所需原子能力取得 C1，自然增强用户效果争取 U1。

### CR1 / CR2 创意对测

- CR1 手绘记忆重构与 CR2 结构套色重组先使用 `CREATIVE-COVERAGE` suite 的同一 `dev/calibration` 来源、同一尝试预算和未来等价输入契约；入围版本改用全新独立 `holdout`，不得复用开发来源。
- 记录全部候选和失败，检查来源可辨认、主体数量、must-keep、变化幅度、效果身份、参考泄漏、假文字 / 水印、延迟和成本。
- 只有首轮达到预注册门槛的方向才冻结版本并做重复性复验。

证据目标：各自独立争取 E1。两者均失败时，混合产品门不通过；主体 / 背景、自然增强、运行、治理和形成性研究照常推进。

## 波次 4 · 无界面闭环、运维与治理

目标：先让真实能力成为可靠服务，再讨论产品界面。

- 建立 `上传 / 读取 → 分析 → 任务资格 → 执行 → 任务 QA → 比较资产 → 下载资产` 的生产等价无界面闭环。
- 冻结来源、任务、设置、引擎 / 配方、参考、QA 与输出规格版本；换图、换任务和关键设置变化后旧响应不得回填。
- 为每个效果冻结 R1 acceptance matrix，逐项声明初态、故障注入、预期页面态 / 任务态、重复次数与通过条件；错误来源下载、旧响应回填、重复计费等安全不变量必须零容忍。
- 以版本化 `O1Profile` 完成幂等、有限重试、`UNKNOWN` 状态恢复、并发 / 队列、超时、取消等待、服务重启、过期响应和错误分类测试，并冻结工作负载、环境、运行次数、错误预算、时延与成本上限。
- 记录延迟、资源、外部调用、成本、失败率和保留 / 删除结果；设置日志脱敏、告警和故障演练。
- 依照 [DATA_FLOW_AND_SECURITY.md](DATA_FLOW_AND_SECURITY.md) 完成数据流、用户处理权、告知同意、保留删除、模型 / 服务条款、安全策略、密钥和审计边界；任何云端夹具上传前先完成 remote-service preflight。
- G1 验证治理机制和账本完整性，逐张来源 / 结果能否展示仍由独立 Release Gate 决定。

证据目标：取得 R1-pipeline、O1 与 G1。一个能力即使已有好结果，也必须等自己的任务契约通过这些边界后才可用于用户研究。

## 波次 5 · 6–8 人形成性测试

目标：在冻结验证前发现任务理解问题，不开发正式产品页面。

- 只使用已有 U1 / E1 且通过 R1-pipeline、O1、G1 的真实任务。
- 可用研究员主持的低保真壳层展示真实来源、参考、结果和失败，不把壳层当作产品。
- 按 [USER_RESEARCH_PROTOCOL.md](USER_RESEARCH_PROTOCOL.md) 邀请 6–8 名目标用户，观察任务卡理解、推荐理由、保留 / 改变边界、必要设置、等待、失败恢复、比较和下载。
- 记录每人的时间、执行次数、求助点、误解、可用性判断与是否主动下载。
- 允许调整任务命名、样例、资格规则、排序、核心文案和交互，因此本轮不计入 V1。
- 可以按已达标任务分别研究；没有创意 E1 不阻塞实用任务的形成性研究，但此时不得称为混合邀请测试。

完成标志：高频误解已处理，未解决问题和取舍有书面记录，可以冻结验证契约。

## 波次 6 · 冻结验证界面与 R1-product-validation

这一波只建设支持冻结任务验证所必需的桌面研究界面，不做正式桌面产品视觉重设计，也不开发移动 / 平板 surface。开始前应满足：

- 四套互斥集合、fixture suite 分配和正式证据已冻结。
- 验证范围内的实用任务取得 U1，创意任务取得 E1；其依赖原子能力均取得 C1。
- 可见任务均具备 R1-pipeline，整体达到 O1 与 G1。
- 6–8 人形成性问题已处理，任务目录、资格规则、参考对、任务契约、QA、核心文案、管线 / 配方版本和成功定义已经冻结。

冻结验证界面只实现：桌面单图输入、冻结任务入口或少量任务卡、必要设置、真实执行、任务 QA、原图 / 参考 / 结果比较、失败恢复和任务格式下载。它不展示模型、Skill、自由 Prompt 或完整工具目录，也不以高保真视觉、移动断点或品牌包装冒充正式产品页面。

证据目标：验证范围内的桌面主路径、错误和恢复状态取得绑定该研究壳版本的 `R1-product-validation`。它是 `R1-product` 的验证阶段 manifest，不自动迁移到之后的正式页面。

## 波次 7 · 至少 18 人冻结验证

- 参与者不得来自形成性测试；招募、知情同意、数据生命周期与退出处理遵守 [USER_RESEARCH_PROTOCOL.md](USER_RESEARCH_PROTOCOL.md)。
- 使用同一个冻结产品版本，不在中途更换任务、模型、配方、参考、QA、排序或文案。
- 每位参与者从自己的合格单图开始，完成一个真实目标任务。
- 核心成功事件：在三分钟内、最多两次真实执行中，得到一个通过任务 QA、本人认为可用并主动下载的结果。
- 正式开始前冻结 `V1Scope`：总体与每个待发布 effect / variant 的最小有效分母、分配方式、ITT / eligible 口径、资格拒绝 / 退出 / 无效会话、主估计量、置信区间、主持人介入上限和停止规则；中途发生实质修改则建立新版本与新一轮样本。

达到预注册门槛后才记录 V1。若未达到，按失败发生在资格、结果质量、解释、等待、恢复还是下载来回到对应证据层，不用新增页面或功能掩盖问题。

## 波次 8 · 混合产品设计入场门

以下三个方向必须同时具备冻结验证阶段的完整证据，才允许开始正式桌面浏览器产品页面重设计；此时仍不开放邀请 beta：

1. `effect.natural-enhance` 取得 U1。
2. `effect.subject-background` 至少一个透明或纯色 variant 取得 U1。
3. CR1 / CR2 至少一个取得 E1。

“完整”指每项依赖 C1、R1-pipeline、`R1-product-validation`、O1、G1、对应冻结范围的 `V1-validation` 和研究界面可见资产 Release Gate 全部成立。只有能力或效果等级、不完整的研究壳、形成性反馈或 E0 样例都不能过门。

正式页面才进行品牌、桌面信息结构和完整视觉设计，并且只展示通过上述公式的任务。若 CR1 / CR2 都没有 E1，底座和实用研究继续，但正式混合页面保持未启动；要改成纯实用产品，必须另行获得用户批准、重写范围并重新冻结验证。移动与其他桌面浏览器不会因桌面页面完成而自动进入支持范围。

## 波次 9 · 正式页面复验与邀请 beta

- 正式页面完成后取得绑定 release surface 版本的 `R1-product-release`；验证壳证据不得直接改名复用。
- 只有预注册等价变更清单内的纯视觉变化，且任务选择、信息层级、控件、断点、状态、文案、时序和数据告知均未改变时，才允许用定向桥接测试迁移 V1。超出清单即对受影响 scope 重新招募并取得 `V1-release`。
- 在冻结的 Windows / Chromium 版本、`1280 × 720` 与 `1440 × 900` 桌面视口重跑 R1 acceptance matrix、可访问性、真实下载、O1 与 G1 变更审计；新增用户可见资产逐项通过 Release Gate。
- 三个方向均满足 release surface 版本公式后，才开放“质量 + 主体 / 背景 + 创意”邀请 beta。

## 邀请 beta 以后

后续能力仍按 `CAP-01`～`CAP-09` 逐项取证，不按竞争产品的工具数量扩张。建议顺序是修复 / 放大、局部清理、构图 / 扩图，再根据真实需求组合商品图、头像或社交场景配方。

以下范围继续后置：

1. 多图逐张和批量。
2. 用户从满意单图中挑选素材后形成的合集。
3. 海报、封面、故事册、模板和自由画布。
4. 特定地区、机构和渠道的官方证件照片。
5. 手机、平板、iPhone / HEIC、Safari、Firefox、触摸专属交互和完整响应式产品。

通用底色头像也需要独立身份保护、构图与文件规格证据；任何官方证件能力还需权威规则来源、版本、地区 / 机构 / 渠道和真实受理边界，不能从通用头像或抠图能力直接推出。
