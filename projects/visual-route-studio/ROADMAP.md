# StoryFold 路线图

路线图按“先证明能力组合能产出连贯图片，再制作产品界面，最后做用户研究”的顺序推进。当前没有调研对象，因此所有产品假设仍为 D0。

## 已完成：能力组合与产品选择

- 核对 Skill Zine Summary 中 13 个图片 Skill 的输入、转换、渲染、产品化和 QA 能力。
- 确认这些能力可以组成生产链，而不是 13 个平行滤镜。
- 比较 StoryFold、Campaign Forge 和 Evidence Canvas 三个产品方向。
- 选择 StoryFold 作为第一产品；把保真预检降为内部合成与 QA 能力。
- 定义固定的六页页面系统、两条叙事路线和首版边界。

依据见 [SKILL_COMPOSITION.md](SKILL_COMPOSITION.md) 与 [DIRECTION_DECISION.md](DIRECTION_DECISION.md)。

## 阶段 0：受控内容样本（首个夹具已完成）

**目标**：在设计界面或招募用户前，证明同一组照片可以被多种能力组织成一个连贯的六页成品。

- 选择一组 4–8 张自有、合成或明确授权照片。
- 编写一份 Story Card 和每张照片的 Evidence Card。
- 固定照片顺序、不可丢失事实与转换权限。
- 写出“现场叙事”和“记忆叙事”两套六页 storyboard。
- 为每页定义来源照片、页面职责、共享 tokens、真实文字和 QA 条件。
- 制作第一份六页静态内容样本；尚不需要完整产品界面。

完成记录：2026-08-11 已用“雨停以前”合成照片夹具完成 Story / Evidence Cards、现场 / 记忆两套 storyboard 与六页视觉概念 sheet，见 [样本记录](samples/rainy-bookstore/README.md)。

阶段出口：

- 两套 storyboard 都有封面、开场、展开、转折、关系过场和收束。
- 每个页面决定都能追溯到 Story / Evidence Card，而不是随机风格。
- 同一照片不会在未授权情况下从“必须原样”变成“重绘 / 抽象”。
- 六页缩略图并排时能看出同一套颜色、mark、字体与叙事节奏。

## 阶段 1：页面生成与确定性合成（当前）

**目标**：实现最小的真实图片生产链，而不是只做视觉 mockup。

- 实现四类原创页面渲染：封面、原照编辑、记忆重绘、关系抽象。
- 建立无字视觉层生成契约，禁止把生成文字当最终文字。
- 实现确定性 compositor：照片窗、真实排字、页码、4:5 / 2:3 比例和安全区。
- 建立跨页共享 tokens：来源色、mark family、字体、留白和装饰密度。
- 按页面缓存生成层与合成结果，支持单页重做。
- 为来源 hash、锁定照片区、文字溢出、顺序、尺寸和结构建立自动检查。

当前进度：电脑网页版确定性合成器已实现 SOURCE contact sheet 直接裁切、两条路线 / 十二个页面状态、真实中文、页码、SHA-256、来源失败拒绝与当前页 PNG 生成。范围和证据见 [COMPOSITOR-CONTRACT.md](COMPOSITOR-CONTRACT.md) 与 [COMPOSITOR-VALIDATION.md](COMPOSITOR-VALIDATION.md)。无字生成层、页面版本 / 缓存和批量导出仍未完成。

阶段出口：

- 同一输入可重放并生成一套完整六页作品。
- 必须原样的照片区域缺失或被错误替换时 fail closed。
- 所有真实文字由确定性排字输出，无生成乱码。
- 单页重做不会修改其他已确认页面。
- 项目可以在本目录独立运行、测试和打包。

## 阶段 2：产品封装与导出

**目标**：把页面生产链变成一个完整可用的本地 MVP。

- 完成照片上传、短故事、事实标签和转换权限输入。
- 展示两套可比较的六页 storyboard，不暴露 Skill 或模型名称。
- 提供页面生成状态、错误说明、单页重做和版本选择。
- 导出六张 4:5 页面 PNG、独立封面、2:3 双面数字纪念卡。
- 生成 PDF / ZIP 与 manifest，记录真实文字、页面顺序、来源和版本。
- 做桌面与移动端的关键流程、响应式、键盘和失败状态验证。

阶段出口：

- 用户可以从空项目走完输入、选路线、生成、单页重做和导出。
- 导出文件与界面确认的页面版本一致。
- 来源、身份、权利或历史事实不会被机器提示包装成已证明。
- 历史路线决策原型与 StoryFold MVP 明确分离。

## 阶段 3：真实用户研究（后置）

**目标**：有调研对象后，验证 StoryFold 是否比普通模板相册提供真实价值。

- 招募 6–8 位有近期照片故事任务的人，使用他们可授权的真实素材。
- 还原他们原本如何整理照片、排故事和制作成品。
- 比较普通模板相册与 StoryFold 的故事表达、事实保留、修改量和分享意愿。
- 测试“现场叙事 / 记忆叙事”是否易懂，是否需要更名或调整差异。
- 观察用户是否愿意补充事实与转换权限，哪些字段被跳过。
- 测试另一位接收者能否仅凭导出包理解页面顺序与关键事实。

阶段出口：

- 至少一个高频场景显示 StoryFold 相比模板有可观察改善。
- 用户不需要理解 Skill 名称也能选择路线和发现风险。
- 用户愿意保存、分享或继续修改最终成品。
- 若没有改善，则收窄题材、调整产品形态或停止扩展。

## 阶段 4：扩展方向（只有证据后）

- **Campaign Forge**：若用户持续要求把选定封面扩展为多尺寸宣传套件，再验证此方向。
- **Evidence Canvas**：若文化、教育或档案任务持续需要照片关系图，再验证此方向。
- **实体成品**：只有完成真实打样、裁切、装订和书写测试后，才讨论印刷与邮寄。
- **团队协作**：只有单人流程持续使用后，才研究共享项目、评论、审批和规则复用。

## 当前优先级

当前进入阶段 1，顺序为：

1. 接入封面、记忆重绘和关系抽象三类无字视觉层。
2. 建立单页版本、缓存与重做边界。
3. 增加六张独立页面的批量 PNG 导出。
4. 输出封面、数字纪念卡与 PDF / ZIP manifest。
5. 在普通桌面浏览器重测真实下载落盘和物理键盘路径。

历史访谈提纲、路线卡与决策原型继续保留，但不再代表当前产品，也不作为 StoryFold 已获验证的证据。
