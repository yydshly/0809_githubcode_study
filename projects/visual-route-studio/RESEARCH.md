# StoryFold 研究记录

## 研究目标

当前研究的问题不是“市场上还缺哪个检查工具”，而是：

> 基于 Skill Zine Summary 已研究的多个图片 Skill，能否构造一个职责清楚、产出完整、能够真正生成图片成品的产品？

当前答案是 StoryFold：用 4–8 张照片和一段短故事生成六页视觉小志、封面与双面数字纪念卡。该方向来自本地能力研究，尚未经过用户采用、付费或留存验证。

## 研究基线

前置研究目前记录：

- 12 个去重仓库与 13 个图片 Skill。
- 127 组 SOURCE → EFFECT、57 个来源路径、129 个静态效果和 2 个实时实验。
- 从输入契约、结构提取、视觉语法、渲染、合成到 QA 的六层能力模型。
- 13 个把单一 Skill 推向产品表面的数字预演。

这些材料支持以下能力判断：

- 多照片排序和故事场景卡可以支撑叙事规划。
- 原照编辑、记忆重绘、关系抽象和封面隐喻是不同转换契约。
- 点阵、有限套色、形态、路径、节奏和留白可以形成跨页视觉语法。
- 生成视觉层与真实照片 / 文字的确定性合成必须分离。
- 产品化需要页面比例、安全区、顺序、导出和失败拒绝，不只是给效果图套框。

这些材料不支持以下结论：

- 用户一定需要或愿意付费购买 StoryFold。
- 13 个上游 Skill 都能直接作为稳定运行依赖。
- 所有上游代码、Prompt、样图和字体都可复制或商用。
- 数字样例已经证明实体印刷、纪实真实性或身份保真。

## 当前研究问题

1. 同一组照片能否稳定映射为有起承转合的六页结构？
2. 不同页面职责能否共享同一视觉语法，而不变成风格拼盘？
3. “现场叙事 / 记忆叙事”是否是用户可理解的选择，而不是内部技术分类？
4. 原照、重绘和抽象页面能否保持清楚的真实性边界？
5. 确定性合成能否守住真实照片、文字、页面顺序和比例？
6. 六页小志 + 数字纪念卡是否构成一个完整、值得保存或分享的成品？
7. 单页重做能否控制生成成本并避免破坏已确认内容？
8. 后续产品应该面向旅行、家庭记忆、摄影故事，还是更窄的首发场景？

## 假设台账

| 编号 | 假设 | 可证伪条件 | 状态 |
| --- | --- | --- | --- |
| H1 | 4–8 张照片可以稳定分配为封面、开场、展开、转折、关系过场和收束 | 多数受控样本无法形成完整六页，或必须虚构事实才能补齐 | D0 |
| H2 | 混合原照、拼贴、重绘和抽象页面，比同一模板重复六次更能表达故事 | 页面职责差异只造成风格割裂，没有增加叙事可读性 | D0 |
| H3 | 用户无需理解 Skill 名称，也能区分“现场叙事 / 记忆叙事”并作选择 | 用户无法复述差异，或选择主要由随机风格偏好驱动 | D0 |
| H4 | 明确区分原照锁定、允许重绘和允许抽象，会提高对成品的信任 | 用户认为权限设置过重，或成品仍让人误解为原始记录 | D0 |
| H5 | 确定性 compositor 能可靠处理真实文字、照片、顺序和版式 | 锁定内容仍经常丢失、错位，或合成层显著破坏视觉质量 | D0 |
| H6 | 六页图片小志 + 双面数字纪念卡是一个完整、可保存 / 分享的产品单位 | 用户只需要单张图、多尺寸套件或更长相册，不认可固定六页成品 | D0 |
| H7 | 共享来源色、mark family、字体和留白 token 可以维持跨页一致性 | 多后端页面即使共享 token 仍像互不相关的作品 | D0 |
| H8 | 用户愿意提供足够的故事事实、照片顺序、转换权限和素材权利信息 | 多数用户跳过关键字段，导致系统只能猜测或无法生成 | D0 |

## 无调研对象阶段的方法

当前只建立工程与内容证据，不模拟访谈回答，也不把内部评审升级为用户证据。

### 1. 受控照片夹具

选择至少三组权利清楚的照片题材：旅行、家庭记忆和活动记录。每组 4–8 张，包含明确的顺序、人物 / 地点 / 时间、不可丢失事实和转换权限。

### 2. 双故事板实验

为同一组照片分别写出“现场叙事”和“记忆叙事”六页 storyboard，检查两者是否在不改变事实的前提下形成可解释差异。

### 3. 页面职责实验

分别验证封面、原照编辑、拼贴、记忆重绘、关系抽象和收束页。记录每类页面最小输入、失败条件和可重做边界。

### 4. 跨页一致性实验

对来源色、mark family、字体、留白和装饰密度建立 tokens，在六页缩略图、单页全尺寸和导出文件三个层级检查一致性。

### 5. 确定性合成实验

用已知缺陷样本测试照片缺失、错误裁切、文字溢出、页码错位、比例错误、顺序变化和锁定区域被覆盖。记录可重复的通过 / 失败条件。

这些结果最多形成工程证据，不升级为 D1。

## 后置用户研究

有真实对象后，优先邀请近期做过旅行记录、家庭纪念、摄影故事或活动回顾的人，使用其明确授权的真实任务。

1. 还原最近一次照片整理与成品制作过程，不先介绍 StoryFold。
2. 让参与者分别用普通模板与 StoryFold 完成同一任务。
3. 比较故事表达、事实保留、修改次数、耗时和保存 / 分享意愿。
4. 观察参与者如何填写转换权限，是否理解原照与重绘的边界。
5. 测试两套故事板的理解、选择理由和页面重做行为。
6. 让未参与制作的人阅读导出成品，复述故事顺序和关键事实。

## 证据等级

| 等级 | 含义 |
| --- | --- |
| D0 假设 | 来自能力研究、内部判断或受控工程样本 |
| D1 访谈 | 来自真实任务访谈，但尚未观察使用 |
| D2 原型 | 用户完成 StoryFold 原型中的关键任务 |
| D3 成品 | 用户完成并愿意保存、分享或继续修改图片成品 |
| D4 生产 | 在真实项目中完成数字交付并记录返工 |
| D5 现场 | 实际发布、印刷或使用后获得反馈 |

数字预演、外部 Skill 样例和内部偏好不能替代本产品的用户证据。

## 主要风险与停止条件

- 多种渲染能力无法被共享 token 统一，六页持续像风格拼盘。
- 为了形成故事必须猜测人物关系、事件顺序或历史事实。
- 原照锁定、真实排字或单页重做无法达到稳定工程边界。
- 多数受控样本更适合单张图或模板相册，固定六页没有增加价值。
- 生成成本、等待或失败率使完整作品不可接受。
- 权利清楚的素材与可用模型条款无法支撑公开样本或产品运行。
