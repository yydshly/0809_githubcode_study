# UI Surface 与桌面可访问性合同

> 文档角色：规定 Single Image Studio 的界面分层、首轮桌面平台范围、研究审阅能力与可访问性验收边界。它不是视觉稿，也不表示任何 surface 已达到 R1 或 V1；当前状态以 [STATUS.md](STATUS.md) 为准，产品状态机见 [V1_FLOW.md](V1_FLOW.md)，用户研究口径见 [USER_RESEARCH_PROTOCOL.md](USER_RESEARCH_PROTOCOL.md)。

## 1. 首轮平台冻结

首轮只为**电脑浏览器**建立产品、运行与用户证据，目标范围冻结为：

| 维度 | 首轮范围 | 冻结方式 |
| --- | --- | --- |
| 操作系统 | Windows 桌面环境 | 由每次研究或发布的 `CompatibilityProfile` 记录精确 Windows 版本、显示缩放与更新日期 |
| 浏览器 | Chromium 系；Chrome 与 Edge 最新稳定版作为候选 | 开始 R1、O1 或 V1 前记录精确浏览器版本和引擎版本；“最新”不能替代证据中的版本号 |
| 最小设计视口 | `1280 × 720` CSS px | 必测主流程、错误恢复、比较与下载；在 100% 页面缩放下不能依赖横向滚动完成主任务 |
| 代表性视口 | `1440 × 900` CSS px | 必测主流程、并列比较、研究审阅布局与关键状态 |
| 主要输入 | 鼠标与键盘 | 拖放只能是便捷入口；选择文件、选任务、设置、执行、比较、删除和下载必须可用键盘完成 |
| 首轮文件边界 | 只接收由独立输入合同和 `CompatibilityProfile` 明确列出的桌面格式 | HEIC 不进入首轮承诺；不能因为某台机器偶然可以解码而宣称支持 |

首轮证据不覆盖移动端、平板、iPhone、触控专属交互、Safari、Firefox、HEIC、macOS、Linux 或完整响应式适配。它们可以在技术探针中被观察，但不得计入首轮 R1-product、V1 或 O1，也不得出现在对外支持声明中。后续扩展必须建立新的 `CompatibilityProfile`、验收矩阵、性能证据与必要的用户研究范围。

现有手机 LAN 页面只属于 R0 工程预览。它可以用于观察页面能否打开，但只能使用合成或明确非敏感资产，不证明移动适配、安全传输、效果质量、性能或可发布性。

## 2. 五类 surface

界面按用途隔离，不用一个页面同时承担工程调试、盲评、用户研究、正式使用和客服排障。

| Surface | 使用者与目的 | 可以展示 | 不得声称或承担 | 证据关系 |
| --- | --- | --- | --- | --- |
| `surface.r0-probe` | 工程人员验证上传、状态、接口和下载骨架 | 调试状态、模拟/探针结果、工程字段 | 产品完成、效果质量、AI 推荐、正式 QA、移动支持 | 只能形成 R0 运行记录 |
| `surface.research-review` | 研究员和独立评审者比较引擎、图层、缺陷与 QA | 多层图像、盲评候选、证据字段、裁决工具 | 面向普通用户的产品体验或 V1 | 支持 C1、U1/E1、QA 校准；自身不取得 V1 |
| `surface.validation-frozen` | 目标用户完成冻结任务 | 与目标产品一致的任务发现、参考、设置、状态、比较、删除和下载 | 调参、引擎选择、研究答案提示或实现细节 | 精确 build 通过 R1-product-validation 后才可取得 V1-validation |
| `surface.product-desktop` | 首轮 Windows 桌面 Chromium 用户 | 仅 `released` 效果和已授权参考资产 | 未发布能力、研究指标、内部 Prompt、模型或 debug 信息 | 精确 build 需 R1-product-release，并有同 build V1 或有效 `V1MigrationManifest` |
| `surface.ops-support` | 受权运维与支持人员按支持码定位问题 | 脱敏事件时间线、阶段、错误码、版本、时延、删除状态 | 默认查看用户图片、Prompt、OCR、EXIF、下载内容或跨用户搜索私人资产 | 支持 O1、G1 与事故调查；不能替代能力证据 |

surface 必须具有独立的路由或构建标识、权限、功能开关和日志字段。研究或运维控件不得仅靠 CSS 隐藏后混入正式产品包；正式用户输入也不得自动进入研究夹具。

## 3. R0 工程探针

R0 保留现有价值：验证单图选择、状态切换、请求形状、结果绑定和下载骨架是否能运行。它必须持续显示“工程探针”身份，并遵守以下边界：

- 模拟结果、本地 Canvas 处理或静态样例必须显式标注，不能冒充真实能力；
- debug 字段不得进入用户截图或对外宣传素材；
- 若通过 LAN HTTP 打开，只用合成或非敏感资产，不发送真实人物、证件、客户图片或访问凭据；
- R0 的浏览器兼容和页面可打开记录不能迁移为 R1-product、V1 或 O1。

## 4. 研究审阅 UI

### 4.1 目标与布局

研究审阅 UI 是下一阶段能力研究的主要视觉工具。它首先服务主体与背景纵向链，也能复用到自然增强与创意效果。桌面布局至少包含：

1. 顶部不可变运行栏：fixture、来源 revision、合同/引擎匿名编号、输出版本、QA profile、attempt 与保存状态；
2. 图像工作区：同一来源的多个图层或候选，支持单图、并列、叠加、滑杆和快速切换；
3. 评审面板：资格、缺陷标签、严重度、局部标记、可用/拒绝、置信度与备注；
4. 证据抽屉：只有提交初判或解盲后才显示引擎、指标、成本、时延与自动 QA 结果；
5. 裁决区：保留各评审者原始判断、分歧原因、第三评审结论和最终决策，不能覆盖原记录。

页面刷新、切换候选或网络恢复后，当前 fixture、视图变换和未提交判断不得错误绑定到其他候选。任何保存动作都必须显示成功、失败或状态未知，不能静默丢失评审。

### 4.2 多层图像合同

主体与背景研究至少能查看：

```text
ImageAsset / NormalizedImage
→ SubjectMap
→ 原始 AlphaMatte
→ 修正 AlphaMatte（如有）
→ ForegroundLayer
→ 黑底 / 白底 / 高饱和底边缘检查
→ transparent / solid CompositeImage
→ 最终 DeliveryArtifact
→ 自动 QA overlay（提交人工判断后显示）
```

所有层使用同一像素坐标与变换基准，并满足：

- 同步缩放、平移、1:1 像素查看和复位；任一面板改变视图时，其他已锁定面板同步；
- 同一光标位置显示各层像素/alpha 与坐标，透明区域不得只靠棋盘格表达；
- 支持边缘放大、轮廓叠加、黑/白/饱和背景切换、前后滑杆与闪烁切换；
- 清楚区分第一遍输出、人工/自动修正输出和最终导出，禁止把修正后结果回写成第一遍结果；
- 不同分辨率或裁切无法像素对齐时明确警告并禁用会误导的同步比较。

自然增强至少提供原图/结果同步缩放、亮度与色彩变化检查及 no-op 选择；创意效果至少提供样例来源/样例结果参考对、用户来源、真实结果和 `must_keep / may_change / forbidden` 对照，不能只展示孤立成品。

### 4.3 盲评合同

- 初判前隐藏仓库、模型、checkpoint、供应商、候选顺序含义、成本、时延、自动指标与自动 QA 结论；
- 使用由冻结分配表产生的随机候选编号，候选 A/B 的位置需平衡，刷新后不得改变身份；
- 文件名、URL、下载名、DOM 文本和错误文案不得泄漏执行器身份；
- 评审提交后锁定原始判断，只有随后独立的解盲步骤才能显示引擎与指标；
- 解盲后允许补充分析，但必须与盲评判断分栏保存，不能改写原始结论；
- 若操作人员因故已经知道候选身份，必须记录盲法破坏并按预注册规则排除或降级证据。

### 4.4 缺陷标签

缺陷分类必须使用版本化 taxonomy，并至少覆盖：

| 范围 | 最低标签 |
| --- | --- |
| 主体完整性 | 主体缺失、误删、孔洞、细节/发丝丢失、非主体残留 |
| 边缘与 alpha | 锯齿、毛边、光晕、色边/溢色、半透明错误、硬边、内部透明度错误 |
| 合成 | 背景残留、边缘不协调、底色污染、位置/尺度错误、导出 alpha 错误 |
| 自然增强 | 过度锐化、色偏、噪声放大、肤色/身份变化、裁切误伤、无有效改善 |
| 创意编辑 | 主体或身份漂移、结构破坏、参考泄漏、虚构文字/水印、must-keep 破坏 |
| 系统问题 | 候选错绑、图层错位、加载失败、过期响应、指标/图像版本不一致 |

每个标签记录区域、严重度、是否灾难级、是否被自动 QA 捕获与评审说明。自由文本只能补充 taxonomy，不能替代结构化标签。

## 5. 冻结验证 UI

冻结验证 UI 只保留普通用户完成任务所需的信息，不能暴露研究审阅 UI 的图层、候选引擎、自动指标或预期答案。它必须：

- 使用冻结 build、效果版本、参考对、关键文案、状态机、错误恢复、删除和下载行为；
- 在 `1280 × 720` 与 `1440 × 900` 的目标范围内完成预注册验收；
- 每次研究记录实际 Windows、浏览器、视口、页面缩放、显示缩放和输入方式；
- 只在目标 `CompatibilityProfile` 内授予 V1，其他浏览器或尺寸只能作为探索性观察；
- 与正式桌面 surface 的任何差异进入 `V1MigrationManifest`，超出预注册等价范围时重跑受影响 V1。

## 6. 正式桌面产品 UI

正式桌面 UI 遵循 [V1_FLOW.md](V1_FLOW.md) 的单图闭环。首轮布局原则是：

- 单一主任务按阶段前进，不复刻历史三栏工作台，不同时展开完整工具目录；
- 来源就绪后，`1280 × 720` 首屏能识别当前图片、候选任务和唯一主动作；
- `1440 × 900` 可提供原图、参考和结果的并列比较，但三态切换始终存在，不能让并列布局成为完成任务的必要条件；
- 图片区域可以受控滚动或缩放，页面主导航、执行、取消、删除和下载不能被图片尺寸推出可达范围；
- 处理、生成、QA、失败、`UNKNOWN`、过期、删除和下载状态均使用真实文本，不用动画或百分比伪装确定性；
- 内部模型、Skill、Prompt、评分阈值和研究标签不成为用户操作项。

首轮允许为两个桌面视口做有限重排，但不把它表述为手机、平板或任意尺寸响应式支持。

## 7. 运维与支持 UI

运维人员通过用户主动提供的 `support_code` 查询单次运行，最低时间线为：

```text
trace_id → user_execution_id → pipeline_attempt_id
→ provider_call_id → qa_job_id → delivery_id → deletion_job_id
```

界面分别显示 execution、surface binding、QA、delivery 和 deletion 状态，并提供版本、阶段耗时、规范错误码、retry 类别、可能计费和数据级别。默认只显示脱敏元数据；查看受限内容必须有独立事件理由、最小权限、审计和期限，且不能绕过用户删除或已撤销的访问。问题定位合同应由后续观测与运维文档进一步冻结。

## 8. 桌面可访问性最低门槛

可访问性同时适用于冻结验证和正式桌面 UI；研究审阅与运维 UI 也必须满足控制层要求。

### 8.1 键盘与焦点

- 所有主任务可仅用键盘完成；拖放、悬停、右键或精细指针不是唯一操作方式；
- 焦点顺序跟随任务顺序，焦点始终可见；弹窗打开时管理焦点，关闭后返回触发点；
- 不设置键盘陷阱；图像缩放/平移快捷键可发现、可关闭且不覆盖浏览器保留快捷键；
- 执行、删除、替换来源等高影响动作有清晰名称和必要确认，重复按键不得创建重复 run。

### 8.2 语义、状态与错误

- 页面区域、标题、表单字段、任务卡、选中状态、进度状态和结果使用真实语义；
- 状态变化通过可读文本与适度 live announcement 表达，不能只靠颜色、位置、动画或图片变化；
- 错误同时指出发生阶段、用户可采取的动作和 `support_code`，并把焦点引导到错误摘要或首个无效字段；
- 样例来源、样例结果、用户原图和用户结果拥有不同的可读标签，避免参考被误认为本人结果；
- 透明度、边缘和缺陷状态同时提供文字/数值，不只依赖棋盘格、红绿或细线。

### 8.3 视觉与运动

- 正文、控件、焦点和状态的颜色对比需通过冻结的自动检查与人工抽检；颜色不是唯一编码；
- 在目标桌面浏览器 200% 页面缩放下，核心操作、错误与下载仍可到达；允许内容区受控滚动，但不得发生控件重叠、裁断或不可关闭遮罩。该要求是桌面可访问性检查，不等于移动响应式承诺；
- 尊重减少动态效果设置；等待状态不使用高频闪烁，前后闪烁比较只能由评审者主动触发、可立即停止且不用于普通用户 surface；
- 图片缩放保留清晰的倍率、复位与适配视图控制。

### 8.4 研究中的边界

视觉质量裁决本身可能依赖视觉能力，不能用“控件可访问”冒充所有人都能完成像素级评审。研究需区分产品流程可访问性与视觉专家评审资格，记录合理便利、辅助技术、主持人帮助和无法覆盖的人群。任何排除都必须在 `V1Scope` 中说明，不能在看到失败后追加。

## 9. Acceptance Matrix 最小字段

每个 validation 或 product build 至少冻结：

```text
surface_id + surface_build + commit
compatibility_profile_id + windows_version
browser_name + browser_version + chromium_version
viewport_css_px + device_pixel_ratio + windows_display_scale
page_zoom + input_method + locale
effect_and_scene_allowlist + reference_pair_versions
state_and_error_fixtures + accessibility_check_version
visual_regression_baseline + run_ids
known_exclusions + evidence_owner + tested_at
```

矩阵至少逐一覆盖空态、来源错误、无合格任务、设置、执行、QA、结果、下载、删除、`UNKNOWN`、`SUPERSEDED` 与 `DETACHED`。Chrome、Edge、`1280 × 720` 和 `1440 × 900` 不能只用一个组合代替全部组合；若通过风险分层减少组合，必须预注册理由和保留的关键交叉测试。

## 10. 首轮完成边界

只有满足以下条件，才可说“首轮桌面产品界面已取得对应证据”：

1. `CompatibilityProfile` 已冻结精确 Windows、Chrome/Edge 版本和两个目标视口；
2. 目标 build 通过状态、错误恢复、删除、下载、键盘和可访问性矩阵；
3. 研究审阅、冻结验证、正式产品和运维 surface 权限及数据边界已隔离；
4. R1、O1、G1、V1 与 Release Gate 均绑定同一 release scope，或存在有效的 V1 迁移记录；
5. 对外说明明确只承诺已验证的 Windows 桌面 Chromium 范围。

页面能在手机、Safari、Firefox 或其他操作系统上偶然打开，不扩大这个证据范围。
