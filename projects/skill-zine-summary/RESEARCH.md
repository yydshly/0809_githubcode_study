- 新批次覆盖人物、多人协作、单人动作、静物、建筑、自然、夜景、产品和 code-native 关系图，逐项记录用途与不能证明的事项。

### 新结论

1. 效果数量与来源数量必须分开：一张来源生成多个效果可以用于控制变量，但不能冒充独立样本量。
2. 单个 Skill 的能力理解需要两条证据链并存：同源横评负责比较路线差异，独立输入负责观察题材迁移。
3. 照片窗口类路线若由整图生成实现，只能标为概念层成立；正式生产仍需确定性嵌入和像素校验。
4. 多人物、身份、商品颜色和实体印刷不能由视觉相似度验收，必须另设成员计数、授权、色彩或物理样张证据。
5. Photo Distill 的新增盐田实验保持 clean-room 代码原生边界，不用图像模型效果冒充可重复渲染管线。

完整题材矩阵、路径、用途与生产下一步见 [Revision 10 独立原图扩样](lab/web/REVISION10-INDEPENDENT-SOURCES.md)。

## 2026-08-09：初次审计

### 证据

- 主上游固定快照只有 `README.md` 和 `pic/`；
- `pic/` 有 42 张 JPEG，对应 14 行、每行 3 张；
- 14 行只链接 12 个唯一 GitHub 仓库；
- 每个目标仓库已固定当前 HEAD 并核对根文件树与许可；
- `gathered-scenes-zine-skill@598ce3c` 的当前树中 `skills/` 路径数为 0；
- 删除前最后的历史实现提交 `176407b` 中仍有两个 `SKILL.md`，使用个人非商业许可证；
- 许可证变更前最后的 `b14cabd` 也包含两份 Skill，快照内的 `LICENSE` 为 MIT；
- 提交 `37d4253` 的信息为 `Delete skills directory`。

### 主要发现

1. 视觉相似不等于技术相同：这批项目跨越 prompt-only、hybrid 和 code-native 三类后端。
2. “是否保留原照像素”是第一层架构分叉，比“纸张/像素/水彩风格”更重要。
3. 最具迁移价值的共同结构是：`source fact → retained relation → abstract mark`。
4. 工程验证集中在 `travel`、`poetic-line` 和 `photo-distill`：`travel`/`photo-distill` 有自动交付门禁，`poetic-line` 是自动结构检查加人工评分汇总；其他项目主要依赖目测和定向重试。
5. `gathered-scenes` 证明汇总型仓库很容易发生文档与实现漂移，不能只读 README 就判断可运行性。
6. 许可证必须成为研究路线的前置 gate；技术最值得学不代表可以复制改造。

### 决定

- 不把主上游图片或任何目标仓库源码复制进研究目录；
- P0 按技术深度排序，但实际先跑 MIT 项目建立安全基线；
- 无许可证项目只学习可概括思想，并独立实现自己的小实验；单人接触上游实现后不宣称严格 clean-room；
- 所有照片实验默认移除敏感 EXIF/GPS；
- 未来横评只使用同源输入、固定尝试次数和明确的验证规则。
