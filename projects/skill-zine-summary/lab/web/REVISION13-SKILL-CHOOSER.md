# Revision 13：从“继续看图”转向 Skill 选型

> 关联材料：[项目 README](../../README.md) · [Web 运行说明](README.md) · [研究总索引](../../RESEARCH-INDEX.md) · [技术架构图](../../TECHNICAL-MAP.md) · [学习路线](../../LEARNING-ROADMAP.md) · [Revision 12 产品系统](REVISION12-PRODUCT-SYSTEMS.md)

## 这一轮为什么不再机械增加图片

前几轮已经回答了“换一种人物、建筑、静物或业务题材后，这条视觉路线还能不能成立”。当前研究账本包含：

- **127** 组图片 SOURCE → 图片 EFFECT；
- **57** 个不同图片来源路径；
- **129** 个静态效果，其中包含 2 个文字驱动效果；
- **2** 个实时交互，共 **131** 个效果证据；
- 13 个 Revision 12 产品系统数字预演，它们复用已有 EFFECT，因此不重复计入效果。

这些数字说明题材覆盖已经足够丰富，却不能自动回答“面对一个真实任务，应该选择哪个 Skill”。继续让 13 个 Skill 各增加一张新图，容易把换人物、换环境、换配色误当作新能力，也会让效果数量掩盖不同输入契约：GC 更值得用文字 brief 检验，Photo Distill 更值得用数据与渲染回归检验，Postcard 更需要功能和实体生产证据，而不是再补一张照片。

因此 Revision 13 的目标不是扩大图片账本，而是把现有证据整理成一个人可以使用的选择入口。`/choose` 只做证据路由与边界说明，不新增 SOURCE、EFFECT 或产品预演，所以上述 **127 / 57 / 129 / 131** 计数保持不变。

## `/choose` 要回答什么

选择器不是风格排行榜，也不承诺替用户自动作出审美决定。它应当先问任务约束，再把读者带到能够验证该判断的现有实验。

### 1. 按用途筛选

- **保留现场并增加编辑张力**：优先观察 Daily、Scenes Gathered、Travel、Photo Relic、Poetic Line 与 Photo Abstract 的照片—解释分工。
- **完全离开照片，保留最少关系或情绪命题**：优先观察 DYY、Scene Distillation 与 GC。
- **把照片转成记忆性重绘或材料语言**：优先观察 Photo Revival 与 Pixel Style。
- **需要参数化、可回归的浏览器图形**：优先观察 Photo Distill。
- **目标本身就是双面、可书写或变量产品**：优先观察 Photo to Zine Postcard。

用途筛选只确定候选集合。最终还必须继续检查真实性、技术路径和产品形态。

### 2. 按真实性契约筛选

选择器应明确区分四种不能混写的承诺：

| 真实性契约 | 含义 | 适合参考的路线 |
| --- | --- | --- |
| 零照片像素 | 结果不显示来源照片，只保留关系、命题或代码图形 | DYY、Scene Distillation、GC、Photo Distill |
| 完整重绘 | 来源只是记忆与材料参考，不承诺身份或像素保真 | Photo Revival、Pixel Style |
| 照片证据窗 | 页面可见来源照片，但若没有确定性嵌入与验证，只能称感知上的证据区 | Daily、Scenes Gathered、Photo Relic、Photo Abstract、Postcard 的多数本地概念实验 |
| 确定性照片锁定 | 随机生成只负责解释面板，代码负责嵌入原图、排版与验证 | Travel、Poetic Line 的本地确定性补证方向 |

“看起来像原图”不等于像素锁定；“完整展示”也不等于字节一致。`/choose` 必须把这两组概念分开显示。

### 3. 按技术路径筛选

- **生成式概念路线**：适合快速探索隐喻、材料和编辑方向，但文字、人数、人物身份与原照区域需要额外检查。
- **生成 + 确定性合成**：生成环节只制作无字解释面板，照片、标题、比例与交付规则由代码承担；适合必须保留来源证据的任务。
- **代码原生路线**：HTML、CSS 或 SVG 直接表达坐标、关系量和色彩角色；适合参数化、批量、交互和视觉回归。

这个筛选表达的是本项目观察到的技术契约，不表示已经运行或复刻任何无许可、限制许可的上游实现。

### 4. 按产品化形态筛选

- 单张封面或主视觉；
- 摄影编辑页、章节页或折页；
- 多成员系列、季度／年度系统；
- 网站、屏幕、展览或教学界面；
- 包装、卡片、明信片与其他印刷产品。

产品形态只说明效果可能进入什么载体。Revision 12 的产品表面与环境都是复用同一 EFFECT 的 HTML/CSS 数字预演，不是实体打样、客户部署、现场安装或业务结果。

## Web 选择工作台如何落地

- 默认 `/choose` 不把 13 张详细候选卡与 13 项地图重复铺开，只展示选择引导和紧凑全量地图；选中快捷任务或组合条件后才展开完整候选。
- 第四维与本节前文一致，是有区分度的**产品化形态**，不是所有 Skill 都相同的“研究阶段”。五种形态分别为单张主视觉、编辑页／折页、系列系统、网站／屏幕／展览，以及卡片／包装／印刷产品。
- 每条详细候选同时关联三种既有题材证据：Revision 10 独立原图扩样、Revision 11 反向题材压力、Revision 12 完整产品系统。页面只显示标题、当前结论与发现并深链原实验，不复制图片路径，也不新增效果计数。
- 候选和全量地图都展示上游仓库与当前许可判断；两个历史 Skill 共享同一上游仓库，因此全量关系仍是 **12 个唯一仓库／13 个 Skill**。
- 每条候选包含一项“下一步怎么测／什么情况算失败”，覆盖下文 A–E 五类可证伪实验。这样选择结果不仅回答“先看哪个”，也回答“怎样让判断更可靠”。

## 证据不是评分

`/choose` 不应出现总分、星级、胜负排名或“图片越多越可靠”的暗示。不同 Skill 的证据类型天然不同：

- 图片 SOURCE→EFFECT 说明某个本地视觉问题在当前案例中是否成立；
- 确定性合成与 hash 说明特定区域是否可追踪、可重建；
- 参数与代码回归说明同一环境中的结构是否稳定；
- 读者盲测才可能说明关系是否被他人理解；
- 打印、扫描、安装或寄送才可能说明实体与现场表现。

选择器可以显示“概念研究”“确定性补证”“受控 A/B”“尚缺读者测试”“尚缺实体证明”等成熟度标签，但不能把这些标签相加为跨 Skill 分数。它的任务是暴露契约、证据和缺口，让读者选择下一项合理实验。

## 五类后续可证伪实验

下一轮如果继续深入，应优先使用现有来源建立会失败的测试，而不是继续扩充漂亮样例。

### A. 识别与语义回收

适用：DYY、Scene Distillation、Photo Abstract。

做法：锁定同一来源，制作 mark 数量、命题或关系路线的受控变体；让未看原图的读者判断动作、方向、关系或情绪命题。

失败条件：读者只能描述装饰风格，无法回收到预先声明的核心关系；或者新增 mark 并没有改善理解。

### B. 来源保真与篡改拒绝

适用：Travel、Scenes Gathered、Photo Relic、Poetic Line，以及任何承诺照片证据窗的路线。

做法：记录来源 hash，分别构造正常候选和故意改字、改像素、裁切、调换成员顺序的候选，再运行确定性检查。

失败条件：被篡改候选仍被标记为通过；或者页面只能目测“像原图”，却无法说明来源字节、缩放与裁切规则。

### C. 单变量与系列一致性

适用：Daily、GC、Photo Revival，也可用于所有需要系列化的产品方向。

做法：同一来源只改变一个版式、抽象度、材料比例或记忆点数量；反过来，固定视觉语法时再更换多个来源，检查系列身份是否稳定。

失败条件：每一版同时改变过多变量，无法解释差异来自哪里；或者系列必须靠重复同一张图才能保持一致。

### D. 可量化渲染与材料边界

适用：Pixel Style、Photo Distill。

做法：预先冻结网点、着墨、色锚、缩略可见性和浏览器／字体配置；建立明显通过、明显失败与边界 fixture。Pixel 的最终材料结论还需真实打印和扫描，Photo Distill 的跨引擎结论还需实际运行不同浏览器。

失败条件：阈值看完目标结果后才移动；未运行的浏览器被伪写为通过；屏幕模拟被称为实体印刷结果。

### E. 产品功能与真实使用链

适用：Photo to Zine Postcard，以及 Revision 12 的全部产品系统。

做法：先用结构化虚构记录测试变量字段、二维码、文字溢出、正反面与多尺寸适配；若要升级为生产结论，再补真实打印、裁切、书写、安装或寄送证据。

失败条件：产品预演只更换外框、没有功能字段；二维码不可扫；裁切破坏信息；或尚未制作实物却声称生产已经完成。

## 许可、来源与发布边界

- 所有上游 URL、固定 commit 与许可判断继续以 [项目 README](../../README.md) 和 [研究总索引](../../RESEARCH-INDEX.md) 所关联的来源文档为准；许可必须绑定到具体版本。
- MIT 只覆盖许可证实际声明覆盖的代码与文档，不自动覆盖示例照片、字体、模型输出、品牌或人物肖像。
- 无正式许可证或限制性许可证项目只用于事实性架构观察和高层行为研究；本项目不得把其代码、模板、提示文本或资产当作可自由改造的共同基础。
- 本页中的 R12 结论均来自本地虚构 SOURCE、本地概念 EFFECT、独立本地代码实验或数字产品预演；单人研究者接触过公开上游材料，因此不声称法律意义上的严格 clean-room，也不声称已经运行上游 Skill 或取得上游官方输出。
- 当前站点继续限于本地研究。生成资产尚未完成逐项公开发布 allowlist，因此本页不构成 GitHub Pages、公开托管或商业再分发授权。
- 数字产品系统不是实体产品，环境预演不是真实安装，使用场景说明也不是客户案例或业务效果证明。

## 完成标准

Revision 13 的选择器只有在以下条件同时满足时，才算完成：

1. 四个筛选维度都从任务约束出发，而不是从图片数量出发；
2. 13 个 Skill 都能显示目标契约、R12 本地结论、不能证明事项和对应证据入口；
3. 页面不生成排行榜，不把效果数、来源数或产品表面数换算成分数；
4. 计数继续保持 **127 / 57 / 129 / 131**，并明确 R12 产品系统不重复计数；
5. 所有“上游”“本地实验”“数字预演”“确定性补证”和“实体证明”使用不同措辞；
6. 公开发布仍保持阻断，直到逐项权利清单与资产 allowlist 完成。

后续实现应继续服从 [技术架构图](../../TECHNICAL-MAP.md) 的真实性与后端分叉，并把真正的综合对照沉淀到 [学习路线](../../LEARNING-ROADMAP.md) 中，而不是把 `/choose` 变成另一页图片画廊。
