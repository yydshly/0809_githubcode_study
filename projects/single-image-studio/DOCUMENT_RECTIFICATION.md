# 文档 / 平面四角裁正体验契约

状态：内部产品 Alpha，实现范围已经由用户授权继续推进。

## 用户目标

把一张轻度斜拍的纸张、画框、海报或包装正面，手动选四角并整理为正视矩形，默认保持原色导出。仅当目标是纸质文字文档时，才按需增加清晰彩色、灰度或高对比黑白处理。

这是一项 repair-led 范围修订：保留已经验证的四角算法、结果预览与导出链，把“几何裁正”和“文档可读性增强”拆成核心步骤与可选步骤。用户已经授权直接继续实现。

## 主路径

1. 上传并确认一张图片。
2. 在任务页选择“文档 / 平面裁正”。
3. 如有需要先旋转方向。
4. 在完整原图上拖动左上、右上、右下、左下四个角，使边框贴合目标平面。
5. 切换“查看裁正结果”，检查是否拉伸过度或选错边缘。
6. 海报、画框、包装和彩色页面保持“只裁正 · 保持原色”；只有纸质文字文档才按需选择清晰彩色、灰度或高对比黑白。
7. 返回选四角继续修改，或生成并下载结果。

## 接受标准

- 任务入口直接说明适用对象、手动操作和本地处理边界。
- 四个角可用指针拖动，也可获得焦点后用方向键微调；操作顺序和角点名称可理解。
- “调整四角”和“查看裁正结果”是显式视图，不把原图选择态冒充结果。
- 结果预览与下载使用同一组坐标、同一渲染器和相同的输出尺寸计算。
- 四角裁正是核心步骤；文档可读性增强是可选步骤，不能让画框、海报或包装用户误以为必须使用扫描效果。
- 四种后处理方式直接呈现在裁正结果预览中；最终下载复用同一像素算法，不以 CSS 近似冒充结果。
- “只裁正 · 保持原色”默认关闭像素增强；清晰彩色与灰度基于当前图片的亮度范围增强，高对比黑白使用局部阈值并明确只适合文字和线稿。
- 无效、自交或过小四边形会在交互时被约束，并在渲染边界再次拒绝。
- 默认四角覆盖完整图片，不会在用户尚未操作时静默裁掉内容。
- 不上传图片、不自动识别边缘、不执行 OCR、不补画遮挡或缺失内容。

## 支持边界

- 支持桌面 Chrome / Edge 当前产品边界，并保留触摸指针事件路径。
- 适合近似平面的轻度到中度透视；不是精密测量或档案扫描工具。
- 当前使用确定性的四边形重采样。弯曲纸张、卷页、强镜头畸变、折痕和反光不会自动修复。
- 扫描效果是确定性的可读性处理，不理解文字、不判断纸张真实性，也不替代档案级色彩管理。
- 导出最长边默认不超过 2048 px，且不放大来源有效区域。

## 覆盖清单

| 阶段 | 路径 / 状态 | 桌面 | 窄屏 | 键盘 | 证据 |
| --- | --- | --- | --- | --- | --- |
| 任务选择 | 本地任务入口可见且文案真实 | required | required | required | DOM / 浏览器观察 |
| 四角调整 | 默认完整、拖动约束、角点标签 | required | required | required | 自动测试 + 浏览器操作 |

| 可选文档增强 | 默认只裁正；彩色 / 灰度 / 黑白切换后预览与输出一致 | required | required | required | 像素单测 + Canvas 观察 |
| 导出 | 与预览坐标和尺寸一致、可重开 | required | same renderer | n/a | renderer / reopen 测试 |
| 边界 | 无效四边形、过小区域、无 Canvas | required | required | n/a | 负例测试 |

## 明确不在本轮范围

- 自动检测四边形。
- 文档 OCR、PDF、多页扫描、自动内容分类。
- 去反光、去折痕、去手指、内容补全。
- 物理厘米 / DPI / 证件规范保证。
