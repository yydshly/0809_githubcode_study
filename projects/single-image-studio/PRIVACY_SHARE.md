# 隐私友好分享副本

> 场景 ID：`UT-PRIVACY-SHARE`
>
> 合同：`local-privacy-share-v1`

## 用户问题

用户需要把一张图片发送到聊天、社区或普通网站，希望减少文件中携带的拍摄 metadata，并控制图片尺寸和体积，但不希望安装模型或上传到额外服务。

## 第一版能力

```text
确认本地来源
→ 保持完整画面比例
→ 限制最长边
→ 以明确白底生成 JPEG
→ 按目标体积多档压缩
→ 从编码 bytes 重开
→ 核对 JPEG、尺寸、体积、像素、hash 和禁止 metadata
→ 下载新的分享副本
```

输出会拒绝 EXIF、GPS、XMP、IPTC、JPEG comment 等当前私密 metadata。ICC / sRGB 颜色描述仍按现有颜色 metadata 边界处理，不冒充隐私字段。

## 明确不做

- 不识别人脸、儿童、住址、车牌、屏幕、票据、二维码或画面文字；
- 不自动打码、模糊、裁掉或涂抹可见内容；
- 不证明原始平台、副本接收方或操作系统已经删除文件；
- 不改变云端 Provider、账号、分享或上传流程；
- 不覆盖原图；
- 不将“清理文件 metadata”描述为“图片完全匿名”。

## 三个公开起点

| 起点 | 最长边 | 文件上限 | 用途 |
| --- | ---: | ---: | --- |
| 清晰分享 | 2048 px | 2 MB | 普通聊天与相册分享 |
| 日常分享 | 1600 px | 1 MB | 默认，兼顾清晰度和体积 |
| 小文件分享 | 1200 px | 500 KB | 对文件限制较严格的场景 |

参数允许继续调整：最长边 `640–2048 px`，文件上限 `100–5120 KB`，背景色为显式 RGB。第一版固定 JPEG；透明输入会在用户选择的颜色上合成。

## 错误与恢复

- 设置错误：任务未开始，图片未上传，聚焦最长边 / 文件上限 / 背景色；
- 本地处理失败：原图保留，可调整尺寸或目标体积后重试；
- 输出 metadata、尺寸、体积、像素或 hash 不合格：结果不得下载；
- 全流程不调用远程服务，因此不存在远程 UNKNOWN 或重复计费。

## 验收

- strict workflow definition 与 task catalog identity 一致；
- 预设、normalize、plan、report 和负例均有纯测试；
- 项目原创输入完成真实浏览器旅程和输出 Blob 重开；
- 结果页明确列出“文件 metadata 已清理”和“可见敏感内容未检测”；
- 原有五条产品旅程保持通过。

## 实施结果

- `UT-PRIVACY-SHARE` 已接入 task catalog、scenario registry、problem-first 入口、strict workflow、runtime profile、设置页、结果检查卡和下载合同；
- 默认“日常分享”为完整比例、最长边 1600 px、JPEG、≤ 1 MB、白色透明底；
- 结果卡逐项核对 JPEG、最长边、文件上限和禁止 metadata 为 0，并固定显示“文件 metadata 清理不等于画面内容匿名”；
- 产品浏览器 run `6b6c6d6e-7f70-4ba9-8fdc-4567890123bc` 使用项目合成图生成 `1440 × 1080`、`38,471` bytes JPEG，六条本地流程 6 / 6 通过；
- 样例浏览器 run `7c7d7e7f-8081-4cba-8aed-5678901234cd` 在 1180 / 390 px 以 2 / 2 通过；隐私分享样例输出 `1536 × 1024`、`290 KB`；
- 完整产品验证 354 / 354，273 个 JavaScript 文件语法通过；
- 没有调用模型、PhotoRoom 或其他远程图片服务。

上述结果证明本地工作流、输出政策与浏览器交付闭合，不证明画面中不存在可识别人物、地址、车牌、文字或其他敏感内容。
