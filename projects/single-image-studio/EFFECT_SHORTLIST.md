## CR1 · 手绘记忆重构

**用户预期**：结果仍能认出原来的主体类别、姿态、关键物件与场景关系，但变成一幅有纸张、笔触和时间感的手绘记忆；不承诺人物身份或面孔一致。

| 契约项 | 内容 |
| --- | --- |
| 必须保留 | 主体类别与数量、主体姿态、关键物件、主要空间关系、1–2 个来源色或记忆细节 |
| 允许改变 | 绘画媒介、背景细节、光线、景深、纸张与时间气氛 |
| 禁止 | 声称照片修复；虚构身份/年代；增加或删除关键人物；从参考样例复制人物、物件或场景 |
| 适合 | 单人、单物、建筑/室内、具有明确情境锚点的场景 |
| 不适合 | 需要面孔精确相似、档案真实性、可读文字、多人身份核验的图片 |
| 主要风险 | 面孔漂移、关键物件缺失、把“记忆感”做成统一棕色滤镜 |

来源方法：Photo Revival 为主；Photo Relic 的时间层次仅作高层研究输入。历史雨夜修车铺样例只作为待复验线索。

## CR2 · 结构套色重组

**用户预期**：主体仍可辨认，但现场被拆成有限套色、网点、剪纸和几何块面的强图形画面。

| 契约项 | 内容 |
| --- | --- |
| 必须保留 | 核心主体轮廓、关键动作方向、重要数量关系、2–3 个来源色角色 |
| 允许改变 | 纹理、局部轮廓、背景、空间分区、网点密度与套色关系 |
| 禁止 | 退化成简单换色；生成可读假文字；把数字半调称为真实网印；丢失人物/物件数量 |
| 适合 | 高反差人物、工业/静物、清楚建筑轮廓、层次明确的场景 |
| 不适合 | 面孔相似度优先、低清晰度主体、细密文字或商品色必须精确的图片 |
| 主要风险 | 五官或数量漂移、摩尔纹、颜色吞没主体、变成普通 8-bit 像素风 |

可见材料语言只参考 Pixel Style 的数字半调。DYY 与 Photo Abstract 只启发后台 Source Card / 关系提取，不进入 CR2 的可见配方，以免和 CR3 串线；配方与实现必须原创。历史结构重组样例只作为 E0 线索。

## CR3 · 极简墨迹关系

**用户预期**：放弃摄影细节，只用少量墨迹、剪影、路径和空白保留原图最关键的动作或空间关系。

| 契约项 | 内容 |
| --- | --- |
| 必须保留 | 预先声明的 3–5 个关系事实：动作轴、接触点、主质量、方向、数量点或色锚 |
| 允许改变 | 对象外观、材质、透视、背景与大部分细节 |
| 禁止 | 把不可识别的装饰称为来源转译；承诺人物身份或准确尺度；自动补写事实 |
| 适合 | 动作人物、单物关系、建筑轴线、路径清楚或有显著负空间的场景 |
| 不适合 | 用户希望保留面孔、服装细节、商品外观或纪实证据的图片 |
| 主要风险 | 语义无法回收；不同来源都变成同一套黑线与色点 |

来源方法：DYY 与 Scene Distillation 的高层关系语言。DYY 没有正式许可证；Scene Distillation 所在仓库的历史 `b14cab...` 快照为 MIT，但后续许可已变化、当前主线已删除实现，且样例资产未逐图清权。本项目不复制两者的代码、Prompt、mark family 或样图，提示与实现全部重新定义。

## CR4 · 原照与记忆印记

**用户预期**：原始照片作为真实证据完整保留，同时新增一个从关键物件、动作或结构提炼出的记忆印记。

| 契约项 | 内容 |
| --- | --- |
| 必须保留 | 授权原图的像素内容、画面边界与来源 hash；一个可追溯的记忆锚点 |
| 允许改变 | 原照之外的纸张、版画/线条面板、间距、组合比例和无字装饰 |
| 禁止 | 让模型重画原照区；把印记解释成历史事实；复制上游版式或提示；自动加入生成文字 |
| 适合 | 档案感、地点记忆、旧物、建筑、用户明确希望保留真实照片的任务 |
| 不适合 | 用户只想获得一张全幅重绘图，或输入本身没有可提炼锚点 |
| 主要风险 | 看起来只是在套模板；印记选择过于主观；合成破坏视觉整体性 |

视觉方法参考 Photo Relic；工程底座采用原创的确定性嵌图、无字生成面板与来源校验。E1 要求半盲评审能把印记追溯到预先声明的来源锚点，且整体不只是普通版式套壳；真实目标用户能否理解这种联系另归 V1，不由内部评审替代。

## CT0 · 保真光色整理

CT0 只作为研究对照：保持完整内容，调整曝光、色温、局部对比、轻微裁切与观看焦点。它用于为后续用户测试准备两个问题的对照材料：

1. 生成级候选是否真的提供了超出普通照片整理的价值？
2. 用户是否因害怕身份漂移而始终选择最低变化结果？

CT0 不得被包装成 AI 创意效果，也不占用任何创意任务位。

## 本轮明确后置

- 多图场景融合、叙事续帧：输入契约不是单图。
- 明信片、封面、海报、故事册、档案板：是产品载体，不是图片效果。
- GC 式概念海报：可接收照片、对象或 brief，但现有最强差异化证据偏文本/概念编译，自动从单图提炼 brief 尚未验证。
- Photo Distill：适合作为确定性关系/QA 方法，不是当前目标中的真实 AI 图片生成。
- 纯场景想象重构：环境发明和参考泄漏风险最高，等首轮保留/失败门禁稳定后再测。
- “Poetic / Travel / Photo Abstract”三个相近名称：合并为后台关系面板方法，不向用户暴露三个近似选项。

## 受控测试集

本附录遵守 [EVIDENCE_AND_RELEASE.md](EVIDENCE_AND_RELEASE.md) 的夹具隔离规则。下面 6 张本项目原创、合成或明确授权的单图只构成 `dev/calibration` 低成本筛选集，每张只含一个可解释任务：

| 夹具 | 必须覆盖的风险 |
| --- | --- |
| 近景人物 | 面孔、五官、服装与主体裁断 |
| 动作人物 | 姿态、四肢、接触点与动作方向 |
| 单一物件 | 轮廓、部件数量、材料和来源色 |
| 建筑/室内 | 轴线、开口、透视与空间层级 |
| 风景 | 地平线、路径、尺度、负空间与色锚 |
| 密集现场 | 多主体数量、遮挡、背景噪声与候选拒绝边界 |

所有夹具需去除敏感 EXIF/GPS，不使用真实品牌、可读店招、未授权人物或容易被误认成纪实事件的素材。

进入正式 E1 复验的候选必须改用从未参与配方、提示、阈值或候选选择的独立 `holdout`：6 类来源每类至少 3 张，共至少 18 张；每个适用来源以同一冻结版本独立运行至少两次。`dev/calibration`、`holdout`、`defect` 与 `escape` 之间不得复用图片、近重复图片或同一拍摄序列。

每个候选在运行前必须声明：适用夹具、预期拒绝夹具、适用分母和最低通过率。不适用或被正确拒绝的夹具用于验证边界，但不计为效果成功；不能在跑完后只挑三张好图倒推支持范围。

## 生成实验协议

### 第一轮：CR1 / CR2 可行性淘汰

- CR1 与 CR2 × 6 张 `dev/calibration` 来源，各运行一次固定配方，共 12 次主请求。
- CT0 不新增创意请求；若同一来源已有冻结的 `effect.natural-enhance` 或 no-op 研究产物，可作为变化幅度对照，否则该对照记为缺失。
- 每次最多允许一次针对单一失败原因的定向重试；它只用于诊断，原始失败不得覆盖或删除，也不计入正式 E1 通过。任何提示改动都创建新的配方版本。
- 任何候选若在三张以上来源出现同类灾难性失败，暂停该候选，不靠继续抽卡挽救。

### 第二轮：冻结配方与独立复验

- 只复验 CR1 / CR2 中达到预注册初筛门槛的候选，不固定数量，也不为凑位复验未达标者；CR3 / CR4 不因本轮结果自动解锁。
- 根据诊断结果为每个候选冻结一份全局生产输入契约和配方版本；若再次改动，创建新版本并重新开始该版本的 holdout，旧版本结果不得混算。
- 改用全新的 6 类 × 3 张独立 holdout；同一冻结配方、相同画幅与相同生产尝试策略至少独立运行两次。不得根据 holdout 结果继续调提示或筛阈值。
- 在看到 holdout 前预注册 `primary_estimand`、来源级双次运行聚合、总体通过率、每类最低通过、适用 / 正确拒绝 / 无效分母、灾难失败上限和置信区间。默认以 `first-pass success` 判断效果稳定性，以 `success-within-2` 作为生产尝试策略的补充；若采用其他主估计量，必须在首个 holdout 结果产生前冻结且不得事后切换。
- 同时报告 `first-pass success` 与产品策略允许最多两次执行时的 `success-within-2`，不得只报告挑选后的最好结果。同一来源两次运行的“任一次成功”不能冒充“两次均守住合同”；两个聚合结果都必须保留。
- 比较独立运行是否都守住 must-keep、是否出现参考内容泄漏，以及效果身份是否仍一致。
- 若未来另行解锁 CR3 / CR4：CR3 必须增加半盲关系回收，CR4 必须增加印记到来源锚点的人工追溯与原照像素检查；这些未来规则不计入本轮预算或结果。

正式盲评使用随机化文件名与顺序，隐藏引擎、配方和候选身份；两名首评独立使用预先冻结的锚点与量表，任一主判定分歧触发第三评审，第三人仍不能按预注册规则裁决时按失败而非从分母删除。记录原始打分、裁决、评审一致性指标及其冻结下限。作者不得在看过结果后修改通过定义。

“最多两次”指用户明确发起的 `user_execution`；每次用户执行内部的 `pipeline_attempt` 与每个可计费 `provider_call` 分开记录。超时 / `UNKNOWN` 不得自动重提并偷偷增加调用数，诊断重试也不得进入正式成功分母。

### 每次必须记录

- `pair_id`、来源/结果 SHA-256、原始尺寸、EXIF 清理状态和输入权利。
- 精确模型、生成 surface/account terms（内置 ImageGen 或 API）、API 路径、日期、质量、画幅、完整提示、每个输入的角色与 hash、请求 ID、耗时与用量。
- 配方版本、must-keep、may-change、forbidden 和模型看不到的人工评审备注。
- 全部候选、失败原因、是否重试、重试改变了哪一条指令、最终选择理由。
- 当日模型条款、输出发布/商用/归属边界的复核记录。

## E1 升级规则

效果必须同时满足以下条件：

1. 只使用独立 holdout、在预先声明的适用夹具分母内计算，并达到预先冻结的最低通过率；至少在三类不同适用来源上通过，不用一张图的多个变体冒充三类证据。
2. 全部正式通过与重复性结果必须使用同一冻结生产输入契约和配方版本，并完成至少两次独立运行；定向诊断重试不计入。
3. 每个通过结果都守住该来源的 must-keep；人数、主体类别、动作、关键身份线索、关键物件或结构错误直接失败。需要生物特征身份精确的输入判为不适用。
4. 与其他候选在 160px 缩略图上仍有明显差异，不只是换色、边框或排版。
5. 第二轮复验仍呈现相同效果身份，不依赖一次幸运输出；分别报告 first-pass 与 success-within-2。若未来另行解锁 CR3 / CR4，其附加追溯规则随新预注册生效。
6. 在受控实验账本中保留至少一个失败案例和适用边界；只有通过发布 allowlist 的失败图才可公开展示。
7. 样例对的来源、结果、生产输入角色、配方、权利、surface/account terms 和模型记录完整。

E1 只代表效果能力，不授予公开展示权，也不证明运行闭环或用户价值。达到几个就只暴露几个；不以 E0 样例凑数，也不把抠图、换底等实用任务冒充创意效果来填创意名额。首版任务组合门槛见 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)。

## 推荐规则草案

候选建议先做“资格过滤”，再做可解释的规则排序，不产生伪造的精确分数。它目前是待验证假设，不称为已证明的个性化 AI 推荐。

| 图片信号 | 候选倾向 | 拒绝/降级条件 |
| --- | --- | --- |
| 单一主体、情境线索清楚 | CR1 手绘记忆 | 面孔精确、身份或档案真实性是主要需求时降级 |
| 轮廓强、对比高、来源色明确 | CR2 结构套色 | 多人计数、低清晰度主体、商品色精确时降级 |
| 动作轴/路径/负空间清楚 | CR3 极简墨迹 | 用户要求保留面孔与材质时拒绝 |
| 原照必须保留且有单一锚点 | CR4 原照与记忆印记 | 没有可解释锚点，或用户只要全幅重绘时拒绝 |

推荐理由只允许使用可观察事实，例如“主体轮廓清楚，蓝色物件可成为套色锚点”。不得写“匹配度 92%”或把审美偏好冒充确定结论。
